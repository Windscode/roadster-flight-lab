# 3.19 历史执行合同显式审阅

## 审阅决定

3.19 保持旧记录的原身份、参数、完整现场、输入、曲线和算法可读、可导出。当前应用没有安装相应旧求解器，也没有声明任何以 3.19 为目标的完整状态迁移器，因此旧模型不能精确重放，也不能通过“当前模型重算”偷偷执行。[执行资格与迁移清单](../dist/experiment-records.js)

本次只将两处每版必审断言更新为 `3.19.0`，没有更改运行时代码、迁移清单、几何合同或物理判据：

- [现场记录合同](../tests/history-contract-3.14.mjs)
- [历史着陆任务合同](../tests/history-task-3.15.test.mjs)

全量回归的第一次失败保留在 `qa/final-regression-3.19/attempt-01.log`。失败来自仍要求 3.18 显式审阅的版本门槛，不应将它删除或作为物理回归成功。

## 检查过的实际边界

在更新断言之前，独立运行了 [本版审阅脚本](../qa/history-contract-review-3.19.mjs)，[结果](../qa/history-contract-review-3.19.json)记录实际加载的 model/build 和运行时代码哈希。

1. 使用真正保存的 3.8、3.9 和两条 3.18 现场记录。没有改旧版本标签，也没有把旧状态重新包装为新记录。`ExperimentPlayback` 的普通与显式重算路径、`executeExperiment`、完整状态准备以及 direct snapshot import 都拒绝旧模型。现场播放路径在物理导入或积分前拒绝；目标完整状态不变，历史加载/导出没有存储写入，原文件字节保持。
2. 从实际当前模型生成新城市记录，再仅令其碰撞几何签名不符。它先通过当前模型执行资格判断，再被物理导入合同拒绝，积分步数为零，目标状态不变。这独立检查了几何拒绝，未用“旧模型不可用”的先行错误代替它。
3. `_routeSurface` 与 `_contactFeedback` 已纳入当前 snapshot。导入函数先检查模型版本和几何，再处理缺省；当前同模型状态中缺少这两个字段时，明确得到无路线地图和空接触反馈，不继承目标车辆正在使用的地图或历史事件。无效路线参数和接触反馈在任何状态写入前拒绝。这些缺省语义没有给旧模型增加迁移许可。[快照导入](../dist/simulation-snapshot.js)
4. 同一 modelVersion 的未知 build 保持原有边界：拒绝精确重放，用户显式选择后可按当前构建重新计算，并保留来源身份；执行结果不标成原构建精确复现。不同 modelVersion 仍须先有显式迁移器。[当前构建与几何验证](../tests/history-compatibility-3.10.test.mjs)
5. 既有历史着陆任务测试逐条验证 3.14、3.15、3.16、3.17 存档的原结果和算法可读、可导出，且无法执行未安装的原模型/构建。原 4 MiB 存储限制和超限只读保护保持。任务 API 会先建立并静置当前模型 fixture，再拒绝旧身份；这里不声称整个 API 调用零准备步，拒绝发生在导入历史状态和启动任务控制器之前。[任务执行顺序](../dist/landing-challenge.js)

最初的独立临时探针把方法计数器写成了可枚举字段，被严格 snapshot 导出器拒绝；可复用审阅脚本改用不可枚举的测试计数器，运行时代码没有变化。该探针修正与实际成功验证都在结果中说明。

更新审阅断言后，`history-compatibility-3.10`、`history-compatibility-3.11`、`history-compatibility-3.13`、`history-task-3.15` 和 `reproduction-verdict-3.9` 五个现有脚本均在 3.19 实际运行并退出 0；完整回归仍由独立的最终 pipeline 记账。这些脚本保留既有历史身份与字节断言，没有放宽失败判据。

本审阅是历史身份、状态合同和数值执行边界验证，不是旧求解器安装证明，也不是画面、原生按键或 GPU 性能验收。

# Roadster Flight Lab 3.17 本地候选启动与试玩

这是在已交付 **3.16** 上继续开发的 **3.17.0 本地候选**。城市驾驶、车辆工坊和风场研究在同一套项目中运行。请把本次 ZIP 解压到一个**新文件夹**，保留原来的 3.16 文件夹与记录；不要把两个版本的 `dist` 合并。

## 1. 启动：默认使用 8318

需要 Python 3；建议使用 Python 3.9 或更新版本。启动器只使用 Python 标准库，不需要安装 Node、npm 或 Git。浏览器需要能运行 WebGL 2。

解压后，`Roadster_Flight_Lab_3.17` 文件夹中应能看到 `launch.py`、`START_HERE.md`、`CANDIDATE_FILES.json` 和 `dist` 文件夹。请完整解压后再运行，不能只从压缩包预览窗口打开一个文件，也不要直接双击 `dist/index.html`。

### Windows

双击 `START_WINDOWS.cmd`。也可在该文件夹的 PowerShell 或命令提示符中运行：

```powershell
py -3 launch.py
```

如果系统没有 `py` 命令而已有 Python 3，使用：

```powershell
python launch.py
```

### macOS / Linux

在终端进入解压后的文件夹，再运行：

```sh
cd "/你的路径/Roadster_Flight_Lab_3.17"
python3 launch.py
```

也可在同一文件夹运行 `sh START_MAC_LINUX.sh`，不需要依赖 ZIP 是否保留了可执行权限。

启动器先校验文件，再打开浏览器：

**http://127.0.0.1:8318/dist/**

默认端口 **8318** 用于区分已下载 3.16 的 **8317**。原服务可以继续运行，不必先关闭。若 8318 已被占用，启动器会退出并说明原因，不会停止或接管原服务。需要另一实例时，自行指定空闲端口：

```sh
python3 launch.py --port 8319
```

Windows 对应使用 `py -3 launch.py --port 8319`。服务只监听本机 `127.0.0.1`；保持终端窗口打开，在该窗口按 `Ctrl+C` 停止本次启动的服务。若浏览器未自动打开，手动打开终端显示的网址即可。

## 2. 确认看到的是本次候选

启动窗口应显示 **Roadster Flight Lab 3.17.0**、完整 Build、Source commit、Source tree，以及已核验的文件数量。身份文件位于：

**http://127.0.0.1:8318/dist/deployment.json**

将其中的 `modelVersion`、`modelBuildId`、`sourceCommit`、`sourceTree` 与本次交付回执核对。它们也记录在 `CANDIDATE_FILES.json` 中。启动器核对全部候选文件的大小和 SHA256，并重新计算所有运行 JS、HTML、CSS 的源码哈希及构建身份；混入旧文件、漏文件或修改源码都会得到具体报错。

只核验文件而不开服务：

```sh
python3 launch.py --check-only
```

Windows 对应使用 `py -3 launch.py --check-only`。若报文件缺失或混版，请把完整 ZIP 重新解压到另一个新文件夹。启动器不会修改原文件或删除已有记录。

这些校验用于发现损坏、漏文件和版本混合；交付 ZIP 本身的 SHA256 以聊天回执为准。

## 3. 先驾驶，再体验独立的受控后空翻

点击“进入城市”，关闭操作说明后开始驾驶。`W / S` 为加速 / 制动后倒车，`A / D` 转向，空格为车轮制动，`C` 切换视角，`Esc` 打开菜单或返回。城市初次进入使用“外部持续供气”；参数面板中的“气源工况”可切换外供与有限储气。

建议先在平直、无遮挡的街段体验：

1. 确认气源为 **350 bar 恒压外部持续供气**，车辆处于四轮正常行驶状态。这个条件假设有外部供气，不表示有限车载气瓶能完成同样动作。
2. 按住 `W` 开始前进，保持 `W`，再**短按一次 `U`**。`U` 是本轮新增的独立“受控后空翻”；它通过真实起跳、俯仰加减速、喷口分配与着陆回控完成动作。
3. 观察动作与仪表；回到 `DRIVE` 后，仍按住的 `W` 会继续驱动车辆。新按其他驾驶操纵键可以接管并取消自动动作，不要把此时的中断当作完整动作失败。

本轮明确协议下的求解器样本中，持续 `W` 后追加 `U` 在约 **4.675 秒模拟时长**后返回四轮 `DRIVE`，质心峰值约 **6.13 米**。浏览器键盘复核也完成了 W 后追加 U，但实际场地是**实验室平地**，未做完整城市路线中后翻动作的原生验收。墙钟耗时还取决于实际运行速度，本轮 SwiftShader 软件渲染中的等待明显更长。这是受控动作的实测样本，不是所有街道、车速、风场和碰撞初态的成功保证；应留出车体旋转及水平行进的空间。

**`E + 1` 仍是手动升降与俯仰请求。** 可以在保持 `W` 时叠加，输入会共同进入控制器，但它不会自动变成 `U`。手动 `1 / 2` 的角速率请求较慢，倒置时主喷口的受力方向和支撑能力发生变化；地面持续 `W / E / 1` 的**数值试验 G 开 / 关两组**均未完整恢复。浏览器原生手动样本是在**实验室平地、G 开启**时执行，也仍倒置；未做原生 G 关闭组。本轮没有把高空成功称为地面问题解决。界面给出手动俯仰的速率与低净空反馈。

`X` 仍为原有的快速滚转。与 3.16 的同工况对照保持约 **3.69 秒模拟时长**后回到 `DRIVE`，累计滚转 **361.18°**、质心峰值 **3.899 米**，同样属于 **350 bar 恒压外供**证据；这些数值也不代表用户设备的墙钟耗时。`U` 和 `X` 都检查气量与净空；默认 350 bar 有限储气的 `U` 冲量预算不足会明确拒绝启动。不要通过连续按键把拒绝理解为输入丢失，也不要将 `T` 补气用于伪装有限气瓶一次任务成功。

物理边界与完整轨迹见 `docs/physics-controls-3.17.md`。其中手动俯仰约 **70.78–71.02 米**的失败 / 成功夹逼，仅适用于报告声明的无风、外供和完整输入时序，是本协议的采样边界，**不是通用安全高度**。严重 **90 km/h、10 cm 台阶**的完整轨迹仍未收敛，峰值接触力仍可达数 MN；本轮修正摩擦冲量量纲与接触约束，未把该严重工况宣布修复通过。普通制动、转向与低速过缝另有回归记录。

## 4. 风场研究：从基线到可解释的 A / B

从菜单进入“风场实验室”，或从研究控制台的“进入风场实验室”按钮进入。按 `M` 打开实验室控制台，在“控制律 / 着陆”中操作：

1. 先选择供气和任务条件，载入“PD 模板”，运行一次“后台同任务研究”。结果进入“任务与算法结果”；也可选择已有的、与当前构建兼容的基线。
2. 在“准备试验”的“风扰 A / B”区域，选择风况、整数“风场种子”和“B 控制器”。可先用默认种子 **31701**；重复时保持风况与种子相同。
3. 点击“运行同风况 A / B”。A 使用所选基线，B 使用界面声明的控制图；完整初态、供气、风序列与控制频率保持一致。
4. 先看两组是否落稳、是否失败，再看固定 **2–6 秒**窗口内的误差与气量，以及全任务稳定时间。窗口包含起飞收敛，不能把全部高度误差归因于风；全任务气量也不能代替同窗气量比较。这里修改的是高度外环，不能把水平误差几乎相同说成横风控制已全面增强。
5. 选择一条结果，点击“在三维重执行所选任务”观察真实求解过程。用工作区的观察切换收起面板，再返回查看曲线；“取消 / 交还控制”可结束当前任务并保留已执行记录。

不同工况、未落稳、失败或窗口不足的结果会明确保留，不会强行排出优胜者。研究继续使用原结果库和同一求解器，详情见 `docs/research-wind-3.17.md`。

## 5. 保存、导出，以及原 8317 记录的迁移

浏览器的任务库存储按**协议、地址和端口**隔离。`http://127.0.0.1:8317` 的旧记录仍在原地址；新候选的 `http://127.0.0.1:8318` 不会自动读取它们。`localhost` 与 `127.0.0.1` 也属于不同地址。初次在新端口看到空库，不表示原记录被删除。

需要转移时，在原 8317 页面用原有导出功能保存任务 JSON，再到新 8318 的“合并导入任务归档”选择该文件。流程库与任务库是不同对象，按相应的导出 / 导入入口操作。迁移期间保留原服务、原文件夹和原下载文件；不需要清理浏览器数据。

完整任务可用“完整任务整库 JSON”备份；单条可用“选中完整结果 JSON”。如果出现“仅本会话 / 未保存”，当前记录仍可用，但关闭页面前应先导出。旧记录可以保留查看；旧城市与本轮城市碰撞几何不同，严格重执行可能被几何身份检查拒绝，不能据此推断记录损坏，也不应把新世界复算冒称原世界精确重放。

导出期间可以取消。状态“已交给浏览器”表示应用已完成文件交接，**不等于磁盘保存已经完成**；请检查浏览器下载列表或保存对话框。若一次导出没有出现文件，先核对页面状态和浏览器下载，保留当前记录。页面保留文件时可用“重新交给浏览器”；避免反复触发长时间挂起的自动化下载。之前外部浏览器调用的长挂起不能单凭现象归因于应用编码故障。

## 6. 画质、证据与交付范围

车辆工坊可查看外观与底盘；正常驾驶中可切换视角、日夜、天气和画质。本轮改善车身主形、连续街段与照明，也保留此前湿路和门灯修复。首次切档可能需要完成资源与着色器准备；等本次切换完成再判断持续帧率。需要本机证据时，可在“车辆与画质”使用“预热 5 秒 + 采集 30 秒”，或“停止并保留采样”。本轮环境中的 SwiftShader 结果不等于用户显卡性能，不能把它作为所有目标 GPU 已通过的证明。

本候选包含可运行资源、3.17 说明和少量关键报告 / 图片。**完整源码历史、原图和失败轨迹单独交付**；它们没有为缩小候选而从历史中删除。最终版本结论以 `docs/release-3.17.md`、`docs/evidence-scope-3.17.md` 与交付回执为准，分别列出已实现、通过、失败与未测。

本轮本地交付不代表公开部署。在本轮交付状态下，公开站仍为旧 **3.13**，公开仓库下载按钮仍指向 `main` 的旧版本。**本轮完整源码以随交付提供的 Git bundle 为准**，不要用公开 `main` 的 ZIP 替换本候选。公开发布仍等待原先那批包含真实设备与项目档案元数据的披露确认；这一等待不影响本候选的独立开发、测试和本地使用。

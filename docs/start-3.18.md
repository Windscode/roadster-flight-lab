# 3.18 本地候选：启动、控制与恢复

这是在已完整交付的 **3.17** 上继续开发的 **3.18.0 本地候选**。请解压到新文件夹，保留旧候选和导出记录；不要合并不同版本的 `dist`。公开网站仍为已上线的 3.16，这个候选不会修改网站。

## 启动

Windows 双击 `START_WINDOWS.cmd`。macOS / Linux 在候选目录运行：

```sh
sh START_MAC_LINUX.sh
```

需要已安装的 Python 3.7 或更新版。启动器先逐项核对候选清单、源码 build 和媒体字节，并检查清单与部署身份一致，再打开 `http://127.0.0.1:8319/`。它只监听本机；遇到占用端口会报错，不会停止已有服务。

仅核验而不启动：

```sh
python3 launch.py --check-only
```

Windows 对应使用 `py -3 launch.py --check-only`；没有 `py` 时用已安装的 Python 3 对应命令。

启动窗口应显示 **3.18.0**、完整 Build、Source commit、Source tree。候选根目录 `CANDIDATE_FILES.json` 与 `dist/deployment.json` 提供同一身份。commit/tree 是打包时记录的 Git 身份；启动器不含 Git 历史，其真实性须与独立 VERIFY 和恢复后的 bundle 对照。不要用旧标签页、旧端口或缓存中的版本作为本轮结果。没有启动器时，也可用普通静态服务器指向 `dist`，但这会跳过启动前的完整候选核验。

## 驾驶与控制权

W/A/S/D 驾驶和转向，空格制动，C 切换相机，P 暂停，ESC 打开菜单。H/E 明确启动辅助飞行，G 打开回平与保高。所有动作仍由实际刚体积分推进，不会设置车身姿态来演示成功。

G 的水平功能是**速度阻尼，不保持世界 X/Z 坐标**。开启 G 捕获当前高度与航向；关闭、重开、松键及普通辅助飞行的碰撞交接，会清理过期参考。普通辅助飞行松键先制动，速度很小后才捕获就近位置。明确的研究位置保持则继续使用用户指定的世界目标。

**G 关闭不等于取消所有已请求动作。** H/E 辅助飞行、X/U 的完整动作、L 着陆和研究保持有各自控制权；H 返回 DRIVE 可关闭普通辅助飞行请求。操作卡会显示喷气控制来源、位置策略、目标与阀门关闭残余推力。车辆仅因碰撞或倾斜离地，在 G 关闭的 DRIVE 下不应自行启动辅助喷气。

X 保留快速、低高度的滚转轨迹，地面起始会接入物理着陆。新落地阶段沿当前支撑面回平，不返回旧水平位置；四轮承重连续确认后交给驾驶。回执出现后仍应能保持四轮，继续 W/转向，而不是长期前翘或被自动升力托住。

U 为独立的受控俯仰后翻。E+1/2 仍然是手动升降与俯仰同时输入，没有被映射为 U。低空手动 W→E+1 仍有倒置接地失败，不能用 U 的成功替代。

## U 的当前边界

当前预检要求初始水平速度不超过 **18 m/s（64.8 km/h）**，横向速度不超过 **1 m/s**，地面支撑坡度不超过 **5°**，规定风峰值不超过 **12 m/s**，并且转向和偏航已经稳定。5 秒名义滑行路径上有 0.25 秒间隔的顶部采样，仍不是完整车壳的连续扫掠保证。真实供气、压力、力矩、净空不足时拒绝；动作中失去升力/供电会撤销原任务，并按剩余真实执行器尝试回收，不把回收等同原任务完成。

恒压外供与有限储气是不同工况。城市入口沿用原有恒压外供；切换到有限气源、采用默认气罐参数时，可用约 **110.6 kNs**，仍不足原预算 **114.8 kNs**，所以 U 保持拒绝。报告中的外供成功均明确选择恒压 350 bar，并非有限储气成功。未修改门槛、补气或隐藏耗气。

## 观察本轮改动

车辆工坊可在固定翼板、轮和悬架状态下查看正面、侧面、前后四分之三与尾腔。官方白车参考链接保留，材料颜色不是本轮主形体改善的替代证明。

城市沿 Weave → Crosstown → Foundry 原有连续街段查看凹入口、浅橱窗、货架和陈列。宽街、细街、连接处仍在完整地图内；没有新增可进入室内或大人群。夜间选择性立面照明来自实际灯具位置，保持原曝光。

研究的风响应面板可指定 A 基线及 B 高度外环，查看高度误差主图和 2–6 s 共同窗口。矩阵提供三个固定种子、两个风向及三个强度档的有界对照。查看 B 不会改变 A 基线；固定窗口气量与全任务气量分列。完整记录保留供气、初态、风计划、失败、取消和未执行组。

较大的完整矩阵存入 IndexedDB，旧 localStorage 记录保留。存储失败或版本冲突会明确显示“仅本次会话”及错误，不能在此状态下假定刷新后可恢复。应使用完整 JSON 归档保存需带走的记录。

## 导出边界

工坊“当前状态 JSON”与研究整库导出分别记录阶段。应用准备有 30 秒截止和取消；“已交给浏览器”并不证明文件已经落盘。浏览器下载栏和实际文件是另一层证据。这个改动不证明曾经 1758/2561 秒的外部工具挂起已经重现或彻底解决。

## 已知限制

- 90 km/h、10 cm 严重台阶的轨迹仍不收敛，MN 级接触力和终态差异保留。本版本不应据此做高速撞阶的物理结论。
- 连续阴影记录覆盖选定运动、转角、相机与昼夜切换；用户 GPU 的持续帧时与所有角度的无闪烁尚未验证。
- 四轮交接通过的是报告所列连续初态、坡面、风和供气组合，不是任意撞击后的保证。
- 车模仍为依据图片的独立简化重建，前白颊、尾部机构与城市远景仍有简化。

## 源码与历史恢复

试玩包只保留运行资源、当前说明和小证据。完整源码历史在单独的 full bundle；incremental bundle 需要原 3.17 commit 及其完整祖先。

界面内原有的“下载完整项目源码”链接指向公开 GitHub `main`，目前仍是 3.16。恢复本地 3.18 必须使用本轮完整/增量 bundle 与 VERIFY，不能用该链接替代。没有原仓库时使用 full bundle：

```sh
git clone --config core.autocrlf=false --branch improve/roadster-3.18 Roadster_Flight_Lab_3.18_full.bundle roadster-flight-lab-3.18
cd roadster-flight-lab-3.18
node scripts/repository-payloads.mjs restore
```

命令禁用 Git 自动换行；否则 Windows 的全局换行设置可能把原始源码转为 CRLF，导致 build 和逐文件哈希不符。在已有完整 3.17 仓库中，可先正常备份，再从增量 bundle 导入新分支；创建新工作区时使用 `git -c core.autocrlf=false worktree add …`，保留原始字节。不需要重写或强推已有分支。核验精确 commit/tree/build 见本轮 VERIFY。历史失败、旧截图和旧版本身份都保留，后续成功不回填旧图或删改失败时序。

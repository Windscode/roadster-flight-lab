## 1. 操控：触发、控制权、能力与实际运动分开看

### X 仍然是原快速低高度动作

原 3.15 用户电脑短按 X 的截图没有抓到明确动作，不能据此判定键没有到达。现在操作区保留触发是否接收、拒绝原因、当前阶段和完整终态回执；编辑框、菜单、图形不可用与诊断矩阵等输入归属原因分别显示。复位后的 P 恢复也修正了启动卡与实际运行状态不同步的问题，输入释放契约继续保留。

X 没有改为慢速高空舒适动作：原滚转参考仍为 **1.5 s**。350 bar、bench、城市静止承载的实际求解器数值例，在约 **3.692 s** 内完成起跳、滚转和轮胎承载着陆；峰值重心高度约 **3.899 m**，实际滚转累计约 **361.18°**。这些数字来自完整数值记录。完整旧 3.15 候选也已在原生浏览器中触发，抓到 rotate／land 阶段并返回 DRIVE。但该次工具请求 50 ms，实际 DOM 事件时间戳相隔 999.6 ms、页面捕获阶段观察回调相隔 1142.7 ms、应用 InputSession 接收记录相隔 1142.5 ms，不能算严格 50 ms 短按通过；三张截图、完整时序与前后源码身份保留为触发证据，短沿时序另核，不把旧版结果当成最后 3.16 验收。[操控专项](physics-controls-3.16.md) · [原始动作数据](../qa/input-action-evidence-3.16.json)

### W/E/1、G 松键回平与累计姿态

累计俯仰/滚转使用相邻四元数的实际相对旋转，和欧拉角显示分开。车辆发生复合运动或碰撞时，某一机体轴累计超过 360° 仍不能单独证明完成了干净后翻；要同时核对完整轨迹、接触、控制阶段与结束姿态。

分配器曾把普通手动角速率控制中不可能实现的负机体 Y 升力也作为追踪目标，压制了可用姿态力矩。本轮仅把这个不可实现的分配目标投影到零，保留原请求、残差、喷口上界、阀门与其他权重。没有增加推力，也没有让 G、X、定姿程序或直接喷口绕过原能力边界。

从声明的 120 m 高度开始，W/E/1 保持 6.5 s、释放 6 s 的数值参考无接触，累计机体俯仰首次达到 360°约 6.083 s；最低高度由约 39.609 m 提至 45.808 m，同时外供气量增加约 **7.835 kg（1.372%）**。不能只报告高度改善而隐藏气量代价。60 m 起始例仍发生接触，原反例完整保留。[分量力与速度闭合](../qa/pitch-force-accounting-3.16.json)

垂直速度的独立逐积分片核算显示，倒置期间主要高度损失来自重力；旧例主升力喷口向下的贡献约 −0.326 m/s，重力约 −31.637 m/s，轴向喷口提供约 +9.537 m/s。候选主升力向下贡献反而约 −0.408 m/s，倒置时长从 3.225 s 缩短到 3.000 s，并伴随上述外供增加。不能把改善写成简单减少向下喷气、省气，也不能把“倒置下坠”笼统归因为全部主喷口一直大力向下喷。

### 高速台阶：修缺陷，同时保留不收敛

轮碰撞支撑从只查中心射线改为轮胎圆弧／宽度几何支撑。初版三站采样会在轻微车身滚转时把支撑点跳到胎侧，产生制动微小偏航回归；这次回归被独立制动测试发现并保留。最终采用连续冠状支撑，正常支撑力仍作用在真实查询点，没有靠增加偏航阻尼、附着或惯量消除结果。[冻结失败与连续性检查](../qa/braking-footprint-3.16.json)

100／200／300 km/h、初始偏航 ±0.00001 rad 的原制动门槛继续使用。错误三站查询的最大偏航约 0.18254／0.02413／0.05966°，修后约 0.000584／0.000573／0.000596°，保留原 <0.01° 条件。轮胎冠状面本身仍是工程近似，并非实车轮胎标定。

高速硬接触附近由同一求解器细分到 960 Hz。产品输入提供器、`physicalStep`、记录和带噪／延迟观测保持 120 Hz；带噪观测在微步中保持，理想反馈控制则按每个实际积分片的当前状态重算。气量、冲量等采用实际积分片总量，记录与重放也保留该契约。[积分时钟与记录](../qa/contact-step-contract-3.16.json)

### 有限气源提前回收

有限气源的原悬停任务在可用余量不足时更早取消原计划，接入既有着陆控制器；不补气、不改为 bench，也不把原任务标成完成。100／125／150／200／275／350 bar 成对数值例中，首次接触前一个 120 Hz 控制态的垂直速度由约 −4.27／−4.50／−4.68／−4.73／−4.77／−2.81 m/s 改为约 −0.84／−0.68／−0.49／−0.71／−0.72／−0.82 m/s；这些是接触前采样值，不是连续碰撞瞬间的精确峰值。外供均为零，结果分别记录“原任务取消”与“回收着陆完成”。[有限气源完整记录](../qa/finite-recovery-3.16.json)

这是一组声明条件下的可比回收策略，不是所有失控姿态的安全保证。原 100 bar 抗扰研究着陆失败继续保留。

## 3. 连续街道与光照

改进沿既有织桥细街、Crosstown 宽大道、东侧路口与机造连接展开，保留原路网与建筑。通过齐平矿物铺装前场、人行边界、树池／座椅、底层开口与雨棚把空旷沥青区域组织成可读街道；机造车道和前轮通行入口继续使用已修正的共享几何。普通街区也采用有预算的底层立面节奏，不只制作一个展示角落。

湿夜的亮铺地和暗楼体分别处理：局部降低铺装漫反射、调整粗糙度与缝隙，补正确位置的实灯与底层空间层次，没有提高全局曝光洗白夜晚。灯光预算保持原等级，昼／夜烘焙使用同一共享实心几何并保留近似范围。[城市实施与精确几何契约](city-quality-3.16.md)

整轮回归额外发现并修复了两项会直接影响成品的缺陷：

1. **门灯在烘焙包络内。** 374 个发光点原来在完整建筑盒内 0.12 m，目标内 0.08 m；独立双面三角形与生产遮挡都证明外部接收点收不到直达光。完整灯具、牌面与支架外移 0.20 m 后，源外净距 0.08 m、目标外净距 0.12 m。每盏灯都验证了灯面→背板→灯座→至少两根支架→真实砌体的实体连接。这次外移保留已设定的光强、角度、湿材质及全局曝光。最后横街几何调整后，白天、夜反弹与夜直接场三套光场均重新烘焙。
2. **湿路反射读写同一纹理。** 原 3.15 同帧 draw 0–4 记录 GL1282，Chrome 也明确报出 feedback loop。仅关闭 shader uniform 不足以解除活动 sampler 绑定。本轮在反射写入期间临时脱离该纹理，离开 render target 后恢复；异常仍作废半写入缓存，不吞掉 GL 错误。[因果、冻结旧逻辑与恢复专项](reflection-feedback-3.16.md)

后续几何与预算检查又发现两项本轮回归。新 Foundry 人行带起初横穿原 z=−100 横街，独立射线对照证明旧 3.15 可通、新路沿阻断；修复把该带起点设为 −84，保留完整 32 m 交叉口开口和原始失败实体。新增立面也使部分旧视点的绘制提交超预算；最终去掉 23,200 个密封薄窗体的墙内不可见面，保留外前表面／UV／LOD，并合并属性相同的封闭玻璃批次，每实例保留颜色、发光与环境反射响应。原 15 个视点门槛均通过，阈值未改；总三角形 1,729,342、批次 1,074，低于 3.15 的 1,760,124／1,172。这是静态提交成本，不能写成用户 GPU 的帧率提升。[逐窗与原预算核验](../qa/city-glazing-budget-3.16.json)

新夜场均与原物理几何匹配；三场所有显式源码与实际体积文件哈希分别核对。[光场身份](../qa/city-fixture-bake-identities-3.16.json) 原生逐 draw 与 14 帧切换结果单列在采集说明中，不能用这两条 CPU 修复直接宣布 GPU 验收。

## 4. 研究、驾驶 HUD 与导出

研究台现在可在 356 px 操作侧栏、宽结果分析和底部观察条之间切换。长控制项、净空／气源诊断与专业指标按需展开；打开研究台时驾驶操作区收起，现场视野不再被两侧大面板同时挤占。观察条保留运行／结束、保存／仅会话和返回入口，复用原控件与数据。

结果首屏从实际完整记录读取落稳时间、平台超调、稳定时间和气量。同条件、同气源、均成功的结果才给受控差值；固定 0–6 s 吞吐与全任务总量分列。旧 3.15 结果仍标原模型，未安装的旧模型精确重执行继续明确拒绝，不能改标签假装回放。

导出统一显示冻结内容、整理数据、生成文件、交给浏览器、取消／失败，保留字节数与各阶段耗时。普通项目 JSON 使用专用 Worker，复杂 JSON 语义走兼容路径；旧异步任务不能覆盖新结果。应用只报告交接，真实下载由 QA 独立检查事件、保存结果、浏览器 failure 与文件内容。[研究工作区、历史契约和导出测量](research-experience-3.16.md)

在同一软件渲染环境与同三条原 3.15 合成记录下，原版整库导出应用交接约 50.9 ms、自动化保存观察约 6.235 s；本轮早期主线程分段编码出现约 44.179 s 应用延迟，已经作为开发回归保存并改用 Worker。最终构建实际复测：应用交接 **1.637 s**、Worker 内编码 **0.356 s**、主线程传输 6.3 ms、自动化保存观察 **7.215 s**，浏览器下载成功，全部记录值一致。输出空白不同导致原版 4,321,548 字节与紧凑格式 2,503,647 字节。修后没有复现开发中的 44 秒延迟，但仍慢于原版这一单次同步交接；进度／取消有成本。不能用本轮测量推断用户之前 42 分钟工具等待的原因。

最终研究原生验收共 9 张实际整页图。经既有挑战按钮新建一次当前模型默认 PD 任务，1,372 个物理步、11.433 s 落稳；任务结束、保存、刷新回读、选择新结果、返回城市全部完成。研究库由 3 条增至 4 条，旧记录全部值保持，刷新前后库字节一致。统计覆盖每个 120 Hz 物理步，导出保留 686 个控制 I/O 点和 230 个显示采样；没有将降采样曲线说成全程录像。[原始报告、下载与 9 张原图](../qa/native-ui-3.16/README.md)

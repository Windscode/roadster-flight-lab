# 3.16 驾驶、研究工作区与文件导出

本轮保留 3.15 已完成的控制图编辑、另存、同条件对照、独立扰动验证和三维重新执行。改动集中在同一应用中的信息层次、控制权交接、结果解释和导出过程；没有另写一个只供展示的物理求解器。用户电脑已经通过的 3.15 研究流程仍是历史验收证据，本轮没有把重新运行旧流程计作新功能。

## 驾驶时看什么，分析时看什么

驾驶 HUD 保留当前供气、实际控制权、风和故障；姿态 P/R、累计机体轴转角、G 回平状态分别显示。X 的触发/拒绝、阶段与终态回执持续可查，不再要求观看者必须恰好抓住三四秒动作中的截图。累计转角取自实际四元数相邻增量，复合运动中某一轴超过 360° 仍须联合轨迹、接触和最终姿态判断。

较长的净空、有限气源储备、当前姿态推力上界、重量、饱和喷口和原始输入导出放入可展开的详情。研究台打开时驾驶操作区收起，避免左右两个大面板同时挤占观测空间。实际 R 复位后的 P 恢复路径也修正了启动卡与运行状态不同步的问题：恢复运行时清除复位卡，恢复驾驶画面，并继续保留原输入释放契约。

驾驶状态区还提供直接可见的暂停／继续按钮，通过同一个生产暂停入口释放驾驶按键。暂停保留当前物理现场和研究目标，恢复反映实际运行状态；图形停止或诊断矩阵占用时不会绕过控制权。

研究台分为三个明确状态：

| 工作区 | 使用方式 | 信息安排 |
| --- | --- | --- |
| 操作 / 观测 | 准备参数、启动任务、保留三维现场 | 356 px 侧栏；详细参数与算法编辑按需展开 |
| 结果分析 | 查看曲线、完整记录和对照条件 | 宽工作区；使用原有结果库、控制图和图表节点 |
| 收起观察 | 观看运行中的三维运动 | 底部状态条保留任务状态、停止和返回入口 |

新建三维任务启动时进入观察状态。结束、未满足落稳条件、取消、控制权交还和是否成功保存仍分别处理；完成提示不覆盖“仅本会话 / 未保存”。返回侧栏或分析工作区复用现有控件，不重新初始化算法、清空历史或伪造任务末态。

## 从结果直接理解“快、稳、省气”

着陆结果使用原记录的全部物理步统计，不从低频显示曲线重新猜测指标。首屏显示落稳时刻、平台超调与气量，并同时给出平台稳定时间、触地垂速、固定 0–6 s 气量和比较差值。记录模型版本可见，3.15 结果在 3.16 页面中仍显示为 3.15。

| 指标 | 口径 | 不应作出的推论 |
| --- | --- | --- |
| 落稳时刻 | 原记录 `stableLandingAtS` | 首次接触不等于落稳 |
| 平台稳定时间与超调 | 原 `hoverSettlingTimeS`、`holdOvershootM` | 更快不自动意味着更平稳 |
| 全任务气量 | 有限气源用瓶装气排出，bench 用外供吞吐 | 外供吞吐不是有限储罐续航 |
| 固定 0–6 s 气量 | 仅当完整覆盖该时窗时提供 | 不与不同时长的全任务总量混算 |
| 比较差值 | 同任务条件、同气源且两次均成功才具备比较资格 | 不同条件或失败结果不强排“最佳” |

专业指标、比较条件、原始事件、控制图与完整 JSON 导出仍然可用。该入口解释既有求解结果，不以一个综合分数掩盖不同取舍。

## 导出分阶段，交接不冒充磁盘完成

原用户电脑一次输入下载等待约 42 分钟，单凭工具等待无法判断应用在哪一步耗时。本轮先测量，再补可观察、可取消的应用过程。共享导出管理器用于输入时序、现场实验、流程、任务、整库及相关 CSV/原文导出，阶段如下：

| 阶段 | 可查数据与行为 |
| --- | --- |
| 冻结内容 | 快照耗时；快照读取失败显示原错误 |
| 整理数据 | 已处理项/字符、耗时、取消；普通项目 JSON 在独立 Worker 中编码 |
| 生成文件 | 文件字节数、Blob 生成耗时 |
| 交给浏览器 | 记录点击下载链接的时刻；保留完整 Blob，可再次交接 |
| 取消 / 失败 | 明确终态与原因，不显示“保存成功” |

界面明确说明应用不能确认后续磁盘下载完成。QA 再独立监听浏览器 download 事件、保存文件、检查浏览器失败结果和实际文件内容，所以应用计时与自动化计时各有自己的边界。

普通项目存档走专用 `export-worker.js`，避免每一小段 JSON 序列化都被昂贵的 WebGL 下一帧阻塞。Worker 传输仍有结构化复制成本，单独记录 `postMessageMs`；Worker 内部编码耗时与主线程等待耗时也分别保存。取消时终止 Worker。具有自定义原型、访问器、`toJSON` 等对象使用兼容的协作式编码路径，保持原 JSON 语义，不经结构化复制静默丢失行为。

输入日志入列时已经深复制并冻结，导出取得事件数组副本，后续物理帧不能篡改正在导出的历史。新的导出任务会取消上一个任务；较慢的旧异步快照返回后也不能覆盖或重命名新的结果。同步快照 getter 本身仍可能短暂占用主线程，本轮没有宣称每一个任意用户 getter 都可中途打断。

### 已测基线与开发中发现的问题

在实际 Chrome WebGL2 / SwiftShader 环境、1440×900、balanced、相同三条 3.15 项目合成记录的研究页面中，原 3.15 导出得到 4,321,548 字节 JSON：应用点击到浏览器交接 **50.9 ms**，自动化观察到下载保存约 **6,234.8 ms**，浏览器下载失败值为 null，全部记录值一致。这是单次本地软件渲染环境的测量，不解释用户此前 42 分钟的等待。

本轮开发中最初使用主线程协作式编码，在 2,503,647 字节的紧凑 JSON 上实测约 **44,178.9 ms** 应用交接时间，其中序列化约 **41,204.4 ms**。该新路径在昂贵渲染下反复让出主线程，形成了真实的开发回归，因此改用独立 Worker。两文件格式空白量不同，但包含完全相同的项目记录值。

最终构建 `81926b47…` 已在同一 1440×900、balanced 软件 GPU 页面实际复测，数据如下。全部是单次测量，不是统计性能基准。

| 路径 | 实际 JSON 字节数 | 应用点击至浏览器交接 | 自动化观察至保存 | 内容与下载 |
| --- | ---: | ---: | ---: | --- |
| 原 3.15 同步导出 | 4,321,548 | 50.9 ms | 6,234.8 ms | 三条记录原值一致；failure 为 null |
| 本轮开发中主线程分片 | 2,503,647 | 44,178.9 ms | 57,802.4 ms | 原始开发回归完整保留 |
| 最终 3.16 Worker | 2,503,647 | **1,637.4 ms** | **7,214.9 ms** | 三条记录原值一致；failure 为 null |

最终 Worker 内编码 355.6 ms、主线程 `postMessage` 6.3 ms、包含返回消息等待的序列化阶段 1,108.1 ms。最终文件 SHA-256 为 `564de43d083f844bfb885cecf6cf1c25acbe0682109867bae8195edf867b5d7e`。这解决了本轮 44 秒开发回归，但应用交接仍慢于原版这一次同步测量；进度、可取消和独立编码有额外成本，不宣称全面加速。原用户约 42 分钟的工具等待原因仍未由这些测量确定。[完整原生导出、布局与保存报告](../qa/native-ui-3.16/summary.json)

## 最终原生运行、保存与返回

最终源代码与三套光场在原生运行前后逐文件经 HTTP 核验一致。9 张实际整页图覆盖操作、分析、观察、导出交接、新任务运行／结束、新结果、刷新回读和返回城市；页面没有横向溢出，操作栏实测 356 px。截图保存前后分别读取 telemetry，运行中的图只具有时间括号。任务统计覆盖全部 1,372 个 120 Hz 物理步；实际导出另含 686 个控制 I/O 点和 230 个显示采样，没有把这两组降采样数据称为逐物理步全状态录像。运行／结束两张图保留了前一步尚未手动关闭的导出回执，其关闭按钮可见；这块临时面板仍会遮住部分右下 HUD。

通过既有三维挑战按钮新建一次当前模型默认 PD 任务，实际完成 1,372 物理步、11.433 s 落稳、2.067 s 平台稳定、404.765 kg 外供吞吐。它用于核对新界面的运行／结束／保存状态；用户已经通过的 Kp 3.2→5.2 另存与对照成果仍保留原身份。新记录包含完整模型构建与末态，单记录导出 870,846 字节，下载 failure 为 null。

本地研究库由 3 条增至 4 条、共 3,373,507 字节，新记录全部值与导出一致，原三条记录全部值不变；真实刷新后库的原始字节完全一致，能选择新结果并返回城市。未增加配额、删历史或用刷新初始化覆盖结果。

该次实际页面异常为 0，原报告仍保存两条资源 404。开发服务器尚无 `deployment.json`，所以应用 telemetry 中提交／源码树保持 null；独立源码核验已经通过，候选打包时写入实际最终提交／树。软件 GPU 与这些页面计时不代表目标显卡性能。原图、完整记录及原始报告见 [qa/native-ui-3.16](../qa/native-ui-3.16/README.md)。

## 历史和容量契约

3.16 的接触支撑与积分诊断发生变化，本轮未声明一个可以恢复旧版本所有内部状态的迁移器。3.8–3.15 已有记录继续按原身份阅读和导出；未安装旧模型的精确重放与旧完整状态迁移在物理导入、积分之前明确拒绝。用户可以在当前模型明确新建任务，不能通过改版本标签伪装成原任务重执行。

历史任务回归同时读取真实的 3.14 与 3.15 合成档案，每组 3 条，保留算法、控制器 I/O、完整末态和文件字节。3.15 美化 JSON 原件超过现有 4 MiB 本地库上限：直接作为旧库时必须只读隔离并保留原文；使用完整同值的紧凑 JSON 可在原上限内正常读取。没有扩大容量阈值、删记录或删除旧库。[历史任务检查](../qa/history-task-3.16.json)

# 3.18 城市街段与运动阴影

本轮沿用完整 3.17 城市，在已有街段中重建可辨用途的浅橱窗、凹入口和门面节奏，同时修复运动中灯光、显示车体与阴影深度更新不同步的问题。城市没有扩地块，也没有缩成展示街；阴影没有关闭。街道外观、动态阴影、渲染预算与用户 GPU 性能分别验收，不能互相替代。

## 1. 从整块门板到浅橱窗

新模块 `street-display.js` 提供书店、日常用品、维修工坊、画廊四种原创建模配置。橱窗具有 0.62 m 封闭浅腔：侧壁、顶底回边、独立后墙、展示搁板和有尺度的物件。外玻璃与后墙相距约 0.535 m，玻璃透明度 0.19、粗糙度 0.14，独立处理深度写入；这使透明玻璃后面有真实可见结构，不再只是换一种颜色的不透明平板。没有创建可以进入的建筑室内。

入口门扇按约 1.10 m 宽组织，把手中心高 1.06 m；把手只出现在实际门位，避免每一块窗都重复门把。四类陈列的用途与既有店招、雨棚、基座共同形成节奏。没有给所有楼的每个开间都加细节，而是优先处理有明确道路地址的连续首层，保留远处的简化立面。

3.17 已有的 166 m 店廊及其四个物理壳体保留；其中 25 处展示位使用同样的浅景深配置。建筑立面中的 187 处展示位、102 处门位仅作为成本清单，不作为街道质感通过标准。[实际几何与材质检查](../qa/city-street-detail-3.18.json)

上层窗户增加确定性的使用差异、局部帘幕和非均匀亮窗，减少整栋楼完全规则的亮格子。它们没有创建新楼层或遮掉原城市。新几何与配置在本项目中编写，未引入新的外部素材包；既有贴图与依赖的许可继续以根目录 `THIRD-PARTY-NOTICES.md` 为准。

## 2. 有选择的上层照明

织桥一段的四栋沿街楼增加八个有可见灯具、有限光程和方向的立面掠光源。灯具使用既有真实光源/传输链，参数强度 145、范围 16 m、锥角 0.29 rad；这些是模型参数，未声称经过实物光度标定。近处直射与远处漫反射各走原有有界路径，没有补虚拟夜太阳，也没有通过全局提高曝光掩盖暗部。

第一版安装在店廊上方的四盏灯被更高的交换厅屋顶遮住，光源到预期接收点的射线检查失败。故障保存在 `qa/city-detail-3.18/first-grazer-blockage.json` 和 `first-report-blocked.json`。随后根据真实屋顶高度移动这四处安装位置，而非关闭遮挡检查。最终八盏均位于外部，射线可到达对应外墙；夜间直射和反弹光、白天间接光均按最终源重烘焙，源哈希与传输 manifest 对应。[最终光源与传输身份](../qa/city-street-detail-3.18.json)

保持同一曝光的实际白天/湿夜对照应同时看完整街道与普通转角。单盏灯的源射线通过，只能说明实现和遮挡关系正确，不能证明整条街已经达到成熟商业游戏的美术质量。

## 3. 城市范围与成本

与精确 3.17 基线相比，物理城市的规范化几何 SHA256 仍为 `4f7d67bf14ad81d8e0b8e3c59016fc61deef77010f3f38ab745e2efa3937a0b9`，114 栋建筑、12 条道路及原有通行净空一致。新橱窗是既有外立面内的视觉浅腔，没有打开穿墙入口。

建筑渲染几何由约 142 万三角形、918 批次，变为约 147 万三角形、955 批次；实际全城与原十五个固定视点仍受原有三角形/提交上限约束，未提高预算。该成本变化不能直接换算成用户显卡帧率。原 3.17 的“批处理修复前后几何等价”报告原样保留为历史证据；3.18 明确重做了部分门面，不能继续对新美术声称与旧几何完全等价。[原十五视点预算](../qa/render-budget-3.18.json)

整轮 attempt 8 发现两个真实预算超限：高档植物区 48 次提交超过 47，极高档俯视 211 次超过 210。新橱窗框架在变为 `edges` 前错误选了 160 m 空间格，同名批次因而可能混入相距较远的 80 m 框架；新背板也错过既有的同响应混凝土归一。修正只调整归组顺序，保留全部实例与材质，结果为 47 / 205，原十五视点限额不变。修前源码和预算失败均保留，本次城市合批实现对应 `2aab3fe94268f58cfc5ad0074d9cfd3de6d39b83bd0380d9a9abfe58b36c92cc`；此前 a347 图仍保留真实阶段身份。[修前诊断](../qa/full-regression-3.18/exterior-budget-probe-before.json) · [修后同路线预算](../qa/full-regression-3.18/exterior-budget-probe-after.json)

旧玻璃优化测试继续对没有重做的地块比较平面、UV、LOD、色彩、发光与反射接线。明确重做的门面由新街道合同和实际街景验收覆盖，未伪造旧版构建器不认识的新橱窗为等价实例。

## 4. 阴影：定位不同来源

运行时“车上明暗闪动”可能来自纹理/法线、shadow bias、分辨率、级联边界、阴影图更新时序或正常的真实光照变化。本轮没有把这些全部混成一种故障。

| 来源 | 本轮处理与证据边界 |
|---|---|
| 法线、材质纹理和已有 receiver-plane 修正 | 保留 3.17 已修表面与材质接线；没有清空法线、换平材质或关自阴影来隐藏问题 |
| 运动头灯的深度图过时 | 3.17 灯具位置每帧跟随车辆，但深度图按 20/24/30 Hz 节流；运动时灯具与其阴影相机可来自不同姿态。3.18 在显示车体、轮转向/悬架或相机变化时按同一显示帧失效并更新深度图 |
| 物理步与插值显示姿态不同 | 环境灯、阴影跟随使用当前显示姿态，不使用尚未显示的下一个物理步位置 |
| 实验室跟随光源与像素游移 | 保持固定方向光偏移，在光源投影坐标中按实际 texel 对齐原点；相机旋转/车辆运动与阴影更新同源 |
| 城市日光级联与转角 | 需要更新时才一起更新 CSM 相机及其深度，跟随真实相机变化；级联分辨率、fade 和既有 bias 未被取消 |
| 投影物范围边缘 | 加入 6 m 范围滞回，减少在刚好可见/不可见门槛上反复加入移除投影物 |
| 正常昼夜/曝光变化 | 真实日夜切换会改变光源；连续观察固定曝光并记录切换时刻，不把正常切换帧算作随机闪烁 |

原 3.17 实际头灯模块的冻结副本只调整 Three 导入路径，在三档各 240 个连续移动/转向显示帧中，深度相机过时分别出现 203 /197 /189 帧，最大位置差约 1.00 /0.85 /0.68 m。当前模块的同序列为零过时帧，保留真实投影开关和灯具。这是 Three 灯光/阴影相机矩阵证据，**不是 GPU 以 120 FPS 渲染的声明**。[逐帧机制对照](../qa/shadow-motion-3.18/report.json)

实验室三个档位各 160 个跟随位置中，独立投影检查的 texel 原点小数残差最大约 5.12e−13，光源方向变化约 4.97e−16；实际保留 1024 /1536 /2048 阴影图和 normal bias 0.032。另有真实城市环境的连续昼夜、转角和相机时序验证。它们定位并关闭了具体更新错误，不能推出不存在任何分辨率锯齿、级联转换或用户设备上的时间混叠。

运动时更及时的阴影更新可能增加 GPU 工作量。本机 SwiftShader 的秒级慢帧与用户显卡不是同一性能条件，不能用软件渲染结果推论用户的持续帧时；用户上一轮约 60–61 FPS 的读数也不是本轮严格帧时分布。

## 5. 连续原生观察与实际街景

连续执行器 `qa/native-shadow-motion-3.18.mjs` 使用实际键盘、鼠标和可见 UI，读取实际应用状态与源响应哈希，分别在冻结 3.17 和当前 3.18 上记录实验室以及城市片段。车辆移动、转向、相机、白天/湿夜和曝光条件与录像一起保存。它不调用模拟器姿态 setter，不跨过物理状态来拼接成功结局，也不以静态工坊图替代运行观察。

街景执行器 `qa/capture-city-3.18.mjs` 从现有固定视点、天气、曝光基线和质量 UI 采集原始浏览器 PNG。每张图旁保存前后状态、相机、质量、曝光及实际收到的源码哈希；这些围绕采图的状态不冒称与 PNG 原子绑定。a347 阶段固定街景按 P 恢复仿真但不给驾驶输入；驾驶机位则由真实 W 持续输入推进，在实际车速下截帧，保存真实模拟/壁钟时长。这一张图不替代连续驾驶与阴影录像。

## 6. 仍然有限的部分

塔楼上层仍有明显的程序化规律；远景玻璃和屋顶设备的种类有限。局部浅橱窗提高了首层深度，但不等于所有街区都完成了独立美术设计。宽街、窄街及跨区连接保持原通行几何，不能用代表性街段的改善冒称全城每个角落都精修完成。

动态阴影保留真实光源和投影物，已修复可复现的更新失配与投影游移；用户实际运行 build 尚未核实，用户 GPU 上的持续驾驶、不同分辨率/档位和全部相机组合仍需分别核验。严重台阶接触、手动后翻和历史下载挂起在其他专项中保留失败/未知状态，与本节的视觉改善无关。

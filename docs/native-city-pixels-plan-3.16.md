## 原有固定视点

| 现有 UI 视点 | 覆盖的实际空间 | 两种天气 |
| --- | --- | --- |
| `weave-entry` / 织桥入口 | 既有细街、人行边界、底层立面和步廊连续灯光 | 晴天、湿夜 |
| `crosstown` / 横街衔接 | 宽大道、铺装与人行道亮暗层次、远景 | 晴天、湿夜 |
| `cross-east-gateway` / 横街工业转角 | Crosstown 到机造大道的跨区接点 | 晴天、湿夜 |
| `foundry-work-bay` / 机造维护庭 | 机造大道的既有维护庭和立面底层 | 晴天、湿夜 |
| `terrace-arrival` / 台地坡顶导向 | 既有坡道上端和上层街道衔接 | 晴天、湿夜 |

这提供 10 组前后、共 20 张原始画面；最终候选另以原 benchmark 的 drive 入口和 camera-btn 切至真实 cockpit，增加白天/湿夜两张主座舱画面，既不转用 inspection 棚拍，也不把它们计为旧版同镜头对照。现有机造固定视点位于服务桥南侧维护庭，不恰好处在导航终点 `[100,0,315]`，因此不会将这张固定图命名为“已驶抵车行入口”。到达终点的正常驾驶视角和是否驶过上层连接，由独立原生驾驶记录判断。

当前脚本在每个版本的采集前和采集后，都以 `auditNativeSourceIdentity` 实际 fetch 全部声明的 JS/HTML/CSS 源码、三种光场 manifest 和全部体积，核完整文件哈希/体积长度及模型构建身份，避免只相信旧 model-build 标签。原十张 3.15 基线采集早于该 helper 接入；其原 report 没有 before/after fetch 字段，使用上述候选文件核验、同帧身份和之后完整 served audit 的来源链，不能倒填为当时的双端审计。采集点击现有 `visual-capture-bundle`，使用应用原始同帧 ZIP。脚本验证 ZIP CRC、PNG 解码、图片名与同帧 JSON 引用、PNG 与实际 drawing buffer 大小、曝光/相机/画质/天气/物理位姿与速度。源代码与几何本来就是比较对象，因此不会要求源码或模型版本相同；两个完整快照分别保留。动画使用各自真实渲染时钟，未暗中同步或重写，相关时间仍在条件文件中。

每组会生成明确的条件差异清单。条件不匹配、下载失败或图片缺失都保留为失败/未完成，不能算有效前后图。原图只按应用 ZIP 的字节解包，不改像素、不生成替代图、不裁切美化。`index.html` 仅以 CSS 展示原始文件链接，便于审读；统计中的亮度与颜色分布来自解码原 PNG，仅用于发现常量/全黑/错误尺寸等问题，不能当作成品效果判定。

## 14 帧实际 draw 矩阵

同一脚本在 3.16 对照后点击现有 `render-program-matrix`。现有协议包含 7 次画质/天气组合切换 × 2 种视点（桥下与车辆），共 14 个 PNG；每个案例另有普通暂停 draw 和导出 draw 的实际材质、FBO、逐 draw 错误报告。未改协议、未新增入口。

核对分三层：

1. **采集完整性**：应用必须 `expectedFrames=14`、`completedFrames=14`、`executionStatus=completed`，且 14 个 PNG 和具名条件文件齐全。
2. **实际 draw**：逐个普通帧与导出帧核保留事件数、链接与绑定、采样器预算、FBO 完整性、main color 的具名类别、逐 draw GL 错误、遗漏事件与未归属 draw；应用 `physicsUnchanged` 必须为真。只看到 console 空不会算通过。
3. **实际画面**：每张原 PNG 仍需打开审读，记录车辆、道路、立面、材质和明显异常。图片解码与 draw 通过不代表视觉质量已通过，也不是路线覆盖或硬件 FPS。

单张同帧 ZIP 的自动化下载等待上限为 180 秒，失败保留具体错误与当时实际状态，不据此推断应用编码耗时。矩阵最长等候 15 分钟，期间每 30 墙钟秒报告现有进度文本。若应用/浏览器失败或超时，脚本通过现有取消按钮结束，并尝试保留应用实际生成的已采前缀。失败矩阵不会替换成离线 shader 结果。可以用 `--matrix-only --run` 在新目录单独补跑；也可以用 `--skip-matrix --run` 将对照和矩阵明确拆成两个串行窗口。

## 与原生驾驶的次序

先完成本脚本、检查原图和 draw 报告并关闭其 Chrome，将 GPU 窗口交回整合步骤完成原生 UI/操控，再在后续独占窗口用 fresh context 执行 [原生驾驶脚本](../qa/native-city-drive-3.16.mjs) 的 `--stage=foundry --max-wall-s=1800`。静态相机不会移动车辆，不能替代沿真实道路驶抵的证据；驾驶记录也不能替代固定相机与同曝光的外观对照。

## 单独矩阵重试的范围

最终 `81926b47…` 的首次 1280×720 运行在首案例完成 1,209 个普通 draw 后，PNG 导出超过应用原有 20 秒期限，输出 0/14 的失败 ZIP 与完整 partialAudit。它和软件渲染上的潜在回读/调度延迟分开记录，未把 shaderFailures=0 当作成功。第二次只将矩阵页面窗口设为 800×450，使用 `--matrix-only --matrix-width=800 --matrix-height=450`，未改原 14 个案例、材质/FBO/逐 draw/物理不变门槛或应用导出期限。原 12 张 1280×720 同条件城市照片保持原件；两种分辨率的证据分别标记。

本轮实际读取用户提供的 3.12 高 / 流畅 / 高原始 PNG、各自条件与 console，以及 3.11 完整采证包中的七隔离、五夜景和驾驶记录。归档哈希、逐帧条件与准确作用范围见 [本轮证据索引](../qa/visual-evidence-3.13.json)。原始用户包未作为未经审查的浏览器导出直接提交到公开仓库。

冻结3.12最终发射 shader 的离线反射独立复现了高档矿物17 / 道路18、极高18 / 19；新组合为高12 / 13、极高13 / 14。完整 active sampler 数组见 [离线链接反射](../qa/city-shaders-3.13.json)，编译条件、无损打包、缓存与内存代价见 [修复说明](sampler-budget-3.13.md)。道路现在具名 **City / scanned asphalt + local puddles**。

3.11 七隔离实际检视画布1651×1244、ultra / studio / 曝光0.92：legacy-shadow密纹在corrected/no-shadow消除，属于已验证的局部接收阴影修复；宽玻璃环境高光仍在no-shadow、在no-environment消失。保留这项成果，不把它扩展为全车所有机位已通过。新接缝、玻璃排序、灯罩与水庭入口的几何证据见 [车辆与南岸](visual-quality-3.13.md)。

3.11 的54 km/h、20%模拟轴4秒工况：事件边界54.268→53.270 km/h，转向窗口120 Hz统计峰值0.113891°，全记录20 Hz样本（速度>1 m/s）在后续制动达到0.630224°。90 km/h松油+50%模拟轴工况起点90.143 km/h，窗口最低69.272686 km/h、下一制动阶段边界69.279672 km/h，峰值1.140063°。两者均为物理dry / μ1.25，不能当湿地、单因素A/B或3.12/3.13真人驾驶验收。旧文案“能量回收”已经在3.12改为机械耗散，本轮不重写旧原始记录。

## 本地补采：先做这三项

1. **主场景矩阵。** 打开城市，保持1280×720视口并等素材就绪，在“车辆与画质 → 织桥·南岸环线 → 渲染完整性诊断”点击“高 / 极高切换检查 + 原始帧 ZIP”。无需手动来回调画质：程序依次执行 high晴天、high湿夜、ultra湿夜、ultra晴天、流畅湿夜、high湿夜、ultra湿夜；每档检查桥下建筑/道路和当前车，保留暂停帧及对应导出帧，输出14张原始PNG和完整JSON。采集中冻结当前物理、拦截控制输入，完成后恢复画质、天气、镜头、曝光和原暂停状态；不会写入新的用户画质偏好。资源就绪与实际帧等待均有20秒上限，超时明确结束并恢复设置，不生成通过报告。
2. **检视矩阵。** 打开车辆工坊，等自然光素材就绪，使用“检视材质切换与绘制诊断 ZIP”。它在当前机位固定模型、悬架、轮角和翼面，执行 high / ultra / 流畅 / high / ultra × 光棚 / 自然光，输出10张原始PNG与各自条件。请同时观察新机盖缝是否稳定、灯罩层次和透明玻璃遮挡是否正确。
3. **运动与正常显示。** 回城市高档湿夜实际驾驶一小段，观察主体、路纹、灯与反射是否持续存在，再点“继续运行并采集实际驾驶帧”。该按钮采实际正在积分的一帧和主材质信息，不将单帧当路线性能。请附一张同一时刻的普通屏幕截图；如仍缺绘，保留ZIP和console错误。若3D根本未创建，入口会禁用，不生成替代图片。

三份ZIP分别回答城市链接/切换、检视、实际运行帧；不要求先完成整条路线才能报告P0是否修复。矩阵PNG已经绑定同次条件与captureId，分辨率/质量不一致时不得拼成严格视觉A/B。

### GPU门禁具体检查什么

- 查询当前设备MAX_TEXTURE_IMAGE_UNITS等真实上限，以16与设备上限较小值验预算。
- 从当前实际WebGLProgram枚举ACTIVE_UNIFORMS，保存每个sampler名称、type、size和绑定unit；数组按size求和。链接失败时active数组为null，不能把无法查询解释成零资源。
- 在实际draw绑定完成后核对CURRENT_PROGRAM、LINK_STATUS和VALIDATE_STATUS，保留program/shader日志及GL错误。默认的错误不会被吞掉。
- 具名材质关联实际物件、实例类型、camera、render target、编译变体和draw调用。必需道路、矿物立面、实例建筑、车辆必须来自主相机的Standard/Physical颜色材质；阴影深度、SSAO法线或反射相机不能替代主体覆盖。
- 同一上下文反复切换，shader失败历史保留。矩阵记录物理初末状态是否完全相同；中断或缺少draw明确失败。
- 诊断使用同步GL查询，会扰动帧时。全部矩阵帧、显式采集帧及其后一帧间隔不参与暂停/驾驶统计，诊断帧不发GPU计时query，也不触发自适应分辨率。

WebGL对active uniform只提供整个链接程序的信息；报告对所有active sampler元素求和作为fragment预算的保守上界。附带的源声明分stage信息只作说明，不冒充驱动提供的逐stage active计数。离线glslang报告另有真实AST逐stage反射，二者口径明确分开。

链接/validate/无GL错误且有draw仍不保证每个像素都符合设计。必须读实际PNG和普通显示，核对实体、材质、透明遮挡、阴影、反射，以及运动时是否闪断。

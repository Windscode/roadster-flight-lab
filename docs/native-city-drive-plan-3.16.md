# 3.16 原生街道驾驶验证方案

状态：平地制动修复及整轮回归完成、原 1280×720 的 14 帧矩阵通过后，已在冻结 `28e9bc41…` / 本地 8317 上完成一次 fresh-context 的完整 Foundry 下层入口原生路线，进程正常退出。原导航显示抵达，车辆刹停并导出 190.4 s / 22,848 步原生记录。运行开始前明确选择既有上限内的 3,600 墙钟秒、280 仿真秒、18 km/h 目标速度，未在进行中改门槛。本文下表仍是规划来源；实际到达、完整输入覆盖、compound 刚体接触采样及外部日志缺口见[本次实际报告](native-city-drive-3.16.md)，不能只用规划表宣称跑通。

## 路线与可执行的短段

使用菜单“进入城市”的原有 `city` 出生点，车辆中心 `[-200, 0.62, -345]`，朝向 `0° / +Z`。在地图选择“2 / 机造服务桥”，点击“导航到车行入口”。脚本首先读取现有导航返回的路线，要求包含原有 `weave-main`、`crosstown-link`、`foundry-main`；不自行把城区空地认作捷径。

| 段落 | 已有道路 / 世界坐标 | 从出生点的中心线距离 | 实际操作 |
| --- | --- | ---: | --- |
| 织桥交换厅 | 织桥细街 `x=-200, z=-262` | 83 m | 直行，可先做短段输入与制动验证 |
| 第一路口 | `[-200, 0, -132.5]` | 212.5 m | 降至约 8 km/h，按 A 向 `+X` 转入 Crosstown |
| 推荐最短连续验证段 | Crosstown `[-150, 0, -132.5]` | 262.5 m | 完成转向后沿宽街再行 50 m，制动停车 |
| 第二路口 | `[100, 0, -132.5]` | 512.5 m | 降速，按 D 转入 `+Z` 的 Foundry 大道 |
| 机造车行入口 | `[100, 0, 315]` | 960 m | 以应用原有“已到车行入口”状态与实际停车共同判断 |

车辆前方为局部 `+Z`，驾驶员左侧为局部 `+X`，因此第一处转向是 A，第二处是 D。本文的世界坐标方向与键位关系直接采用 `dist/controls.js`、`dist/physics.js` 和 `dist/city-navigation.js`，不按照屏幕地图左右猜测键位。

**默认执行段是“细街 → 一个转向 → Crosstown 50 m”。** 262.5 m 的连续运动足以验证本轮改善的细街与宽大道之间的一个真实衔接；它不会被标成“到达机造”或“全路线通过”。`--stage=foundry` 才请求 960 m 两个转向。上层连接属于另一个待执行范围：即使下层机造入口通过，也不能据此宣称驶过原有坡道或到达 8 m 台地。

## 脚本运行

脚本：[native-city-drive-3.16.mjs](../qa/native-city-drive-3.16.mjs)。直接执行只输出方案，不打开 Chrome、不操作页面、不写仿真状态：

```sh
node qa/native-city-drive-3.16.mjs --stage=crosstown
```

取得本轮串行窗口后执行：

```sh
node qa/native-city-drive-3.16.mjs --run --stage=crosstown --max-wall-s=900
```

本轮完整原生连续路线使用新的输出目录执行：

```sh
node qa/native-city-drive-3.16.mjs --run --stage=foundry --max-wall-s=3600 --max-sim-s=280 --cruise-kmh=18 --url=http://127.0.0.1:8317/ --build=28e9bc415a0509990cb88dcbb0a95117f013969e2283260208df5921c54b1d8f --out=<新的绝对目录>
```

每次运行默认创建带时间戳的独立目录。已有结果和中断目录均拒绝覆盖。可用 `--out=/absolute/path` 明确输出位置，用 `--url=http://127.0.0.1:8316/` 指向候选。默认 Chrome 和字体路径沿用本轮已经实际运行的环境，也可通过 `ROADSTER_CHROME`、`ROADSTER_FONTCONFIG` 覆盖。

页面使用新的浏览器上下文、960×540、balanced、晴天、原有默认干地与转向辅助。画质和天气由现有菜单选择，不修改气源、物理步长、时间倍率或车辆参数。速度目标默认 18 km/h，转向附近约 8 km/h；命令行允许 8–24 km/h。每轮动作等待实际遥测，不能把墙钟按住 2 秒当作车辆恰好运行 2 秒。主循环每 30 个墙钟秒输出实际位置、速度、仿真时间与余程，便于外部确认软件渲染仍在推进。

## 真实输入与数据链

全部车辆动作来自 Playwright 的原生键盘 `down/up`，实际按键仅用 W、A、D 和 Space。S 在本应用先制动、低速继续按住后会进入倒车，本方案在停车时直接使用 Space。驾驶过程中不打开参数面板，不调用 sim 或身体状态的 setter，不导入车辆快照，不调用控制采集自动驾驶，不改写 DOM 的 input event，不写独立的车辆求解器。

外部 QA 操作者读取公开的 `roadsterLab.getState()` 和 `getCityNavigation()`，以当前导航折线的前方目标、实际速度、航向和实际道路转角决定下一组按键。这里的前方目标只是选择驾驶键的参照，实际车辆全部由应用的同一个物理求解器积分。由于它是程序选择按键，结果只能证明该具体输入序列的原生响应、路由和碰撞观察，不能代表人类驾驶手感。

脚本点击工程遥测中已有的“记录这次驾驶 / 飞行”，实际记录开始后才驾驶。终点或中止时，通过同一按钮结束并保存，再打开现有“现场实验记录与导出”并下载“选中记录 JSON”。不从离线求解结果拼装原生记录。

每次运行保留：

- `plan.json`：请求的段落、条件、预算与边界。
- `ui-actions.ndjson`：真实菜单、地图、录制、保存、导出的请求和返回时刻。
- `key-requests.ndjson`：每个 W/A/D/Space 按下、松开的请求与返回；工具命令返回不等同应用接收。
- `received-input-events.ndjson`：持续读取现有输入日志并按序号去重保存；任何序号缺口和应用自身滚动丢弃计数分别记录。
- `telemetry-navigation.ndjson`：实际位姿、速度、接触、g 值、焦点、暂停状态、导航偏航和到达状态。
- `key-decisions.ndjson`：每轮读取之后选择的按键及其依据；不替代应用接收证据。
- `native-experiment.json`：应用实际保存并由现有 UI 导出的完整记录，含完整初态、原版本身份、原始和实际应用输入区间、事件、末态与统计。
- 实际起点与终点 PNG、`report.json`：清楚区分到达、部分完成、失败、保存失败和导出失败。

遥测/导航抽样并非逐接触冲量审查；报告不会用接触计数直接宣称撞击严重程度。保存的完整应用记录保留该记录系统已有的逐物理步输入与统计。普通 W/A/D 不会凭空开启 20 秒姿态细跟踪，脚本也不为加密日志而发送 G/E/1；应用接收日志和完整实验输入是相互补充的不同证据。

## 中止和完整性

真实导航偏航持续超过 0.5 仿真秒、刚体接触持续超过 0.3 仿真秒、四轮离地超过 1 仿真秒、异常姿态/倒车、应用拒收驾驶键、实际暂停/焦点变化、求解错误、原始记录提前结束或既定预算到期，都会保留当前失败或部分结果。不会 reset 再把新片段拼成一次通过。正常或异常结束先尝试实际 Space 制动，至多 3 仿真秒 / 30 墙钟秒，然后使用现有暂停按钮，保存已经发生的真实结果。

软件 WebGL 的墙钟成本可能先耗尽，已有记录的上限则是 300 仿真秒；脚本最大预算为 285 仿真秒，默认完整路线 280 秒，以留下最终制动和保存余量。单次脚本不能据超时宣称应用制动失效；需要对照最后的实际仿真时间、输入接收和实际制动力/速度变化。PNG 与紧接着的遥测是分开的浏览器操作，没有冒称同帧原子快照。实际完成后的图片和完整记录应再由操作者审读。

## 手工式退路

若自动选键在首个路口不稳定，先保留失败记录。人工式短段方案仍可在同一合法出生点执行：菜单进入城市，地图选机造车行入口，开启记录；以 W 短按/松开将速度维持在 15–18 km/h；导航提示首转小于约 18 m 时松 W，以 Space 减至 8 km/h 左右；行至路口按 A，同时仅以必要的 W 短按保留滚动速度，观察车头接近 `90°` 时松 A；沿 Crosstown 直行约 50 m，再以 Space 停车、结束保存和导出。所有判断以实际画面和导航/遥测为准，按键的墙钟时间不能预先当作确定距离。

该退路没有声称已经执行；其用途是为真实浏览器窗口提供明确、短且可观察的操作对象，避免在没有新的原生驾驶证据时引用旧数值路线作为替代。

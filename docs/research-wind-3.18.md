## 1. 本轮真正改变了什么

- 高度外环的改动现在对应到主图：`实际高度 − 目标高度`，A 绿实线、B 金虚线。零误差参考线和 2–6 s 阴影清楚分开；风速是 A/B 共同的规定风序列，避免重叠曲线暗示不同外扰。曲线来自保存的 **20 Hz 实际积分状态**，指标仍来自所有 **120 Hz** 物理步。[图表实现](../dist/wind-response-chart.js)
- 单对试验新增横风/前后风选择。小矩阵每批固定同一风强度、种子 `31701/31702/31703`、两个方向，各执行 A/B；静风只保留一个方向，三个种子在物理上是同一零风工况的重复。比较另一强度需明确开下一批，并保留 A 基线与种子。[矩阵实现](../dist/wind-matrix-study.js)
- UI 分别显示落稳/执行数、未执行数、完整窗口数、高度误差分布、同窗气量、全任务气量和分配/控制图受限时间；可直接点 A/B 回看原记录。完整档案保留每个任务的初态、控制器图与内部状态、风计划、末态、120 Hz 控制决策、20 Hz 展示样本和失败事件。导入会核对计划/种子/方向、控制器身份、模型与物理初态链接以及由原记录重算的配对摘要。[结果界面](../dist/landing-research-ui.js)
- 现有结果库增加小型 IndexedDB 适配层，仍保存同一种完整 JSON 归档。没有另建平台，没有抽稀控制记录，也没有自动驱逐旧记录。原 localStorage 文本原样保留。只有事务完成才显示“已保存”；两页同时修改时拒绝旧 revision 覆盖，损坏档隔离并可导出原文。[存储实现](../dist/landing-archive-store.js)
- 检视页的“导出当前状态 JSON（独立）”接入统一有界导出管理器，记录事件阶段和耗时。原来在点击路径内重复查询 GPU 静态身份的操作移到 renderer 创建后缓存。状态 JSON 仍明确是点击时的独立状态，不附会此前 PNG。[检视事件链](../dist/vehicle-inspection.js)

没有把 3.17 已有的保存、三维重执行、单 seed 31701 成功再次算作新功能；既有三维重执行按钮继续复用原求解器。本轮未新建动画演示或绕过现有物理的挑战。

## 2. 试验合同与可恢复条件

### 固定项

恒压三批共用同一个完整快照 `fnv1a32-a682ecdc`，碰撞身份 `08604efb`。初始世界高度约 0.5970 m，世界位置 X/Z 为 0；物理时钟已走过 2 s 的地面收敛过程，研究任务另从相对 t=0 记时。初态中的速度、轮胎/悬架状态、刚体求解缓存、阀门状态、风/观测状态、参数和硬件均随快照保存，不是仅设置一个高度开始动画。[完整恒压原始记录](../qa/wind-matrix-3.18/final/strong-bench.json.gz)

两种控制器都为 60 Hz 高度外环，物理 120 Hz；四个有界状态槽及前次输出初始都为零。A 为原 PD（P=3.2，D=3.6），B 为已声明候选（P=5.2，D=3.1）；输出与变化率限值仍沿用合法控制图范围。水平、姿态、喷口分配、气体和接触仍来自现有物理代码，没有为矩阵改变质量、惯量、喷口推力或气源预算。

固定硬件的关键项：干质量 1950 kg、600 L 气瓶、350 bar 初始压力、50 bar 调压、293.15 K、等熵喷口、四主升力喷口各 20 kN 上限、阀门上升/下降时间 0.045/0.025 s。恒压外供初态含车载气体质量约 249.5582 kg，总刚体质量约 2199.5582 kg；外供吞吐与车载排气分列。有限 100 bar 是独立的低供气初态，不能与恒压组混作同条件控制器优劣比较。

任务目标世界高度 2.5 m、落地区域半径 1.5 m、超时 16 s、喷口健康比例 1。实际落稳仍由原任务的接地、姿态、速度和持续稳定条件决定。结果既保留首次接触，也保留最终落稳时刻。

### 变化项

同一配对只改变已声明高度图。风场不是 CFD 或随机大气；种子确定分段风速、方向和正弦阵风周期。中风配置以 `12 + 4 m/s` 为档名，强风以 `20 + 10 m/s` 为档名，实际每段均按预先声明的种子系数变化；档名不是恒定实测速度。方向对照把同一组方向角旋转 90°，分别形成固定实验室坐标中的横风与前后风。每对 A/B 使用完全相同的风计划与绝对物理时钟，不能把不同风计划互相排名。[风计划算法](../dist/wind-control-study.js)

公共统计窗口是任务相对时间 2–6 s，完整窗有 480 个物理样本。它仍包含起飞目标收敛；不能只因名字叫“风扰研究”，就把全部高度误差当成风造成的误差。三个种子是小范围确定性敏感性样本，成功比例和 p90 都不代表总体天气概率。p90 是这三个样本的线性分位插值；UI 优先显示更易读的中位数和最大值。

## 6. 当前状态 JSON 的事件链与边界

本轮定位的是检视页独立状态 JSON：旧路径为按钮 → `metadata()`（其中重复 `gl.getParameter`）→ 同步 JSON.stringify → Blob → anchor.click → 1 s 后撤销 URL。它没有走已有任务库导出的进度/取消管理器。任务库曾成功下载不能证明这个旧路径没问题。

新路径先在 renderer 创建后缓存不变的 GPU 身份；点击时再获取当前相机/车模/状态 → 有界准备 → 兼容性扫描 → 专用 JSON Worker（不适合结构化复制的特殊对象走精确保留语义的合作式编码）→ Blob → 浏览器交接。准备总上限 30 s；不响应的异步 snapshot 或 Worker 会失败并保留具体阶段，Worker 终止，未准备出的空文件不会被交给浏览器。异步兼容性扫描分段让出事件循环；原有取消、后发导出替换前发与 JSON 语义回归保持。[导出管理器](../dist/export-download.js) · [有界失败证据](../qa/export-deadline-3.18/report.json)

一次实际检视页测试（保留当时 5b9 阶段 build 身份；最终仅新增导出卡语言重绘，序列化/交接路径不变）得到 **5451 字节**独立状态 JSON：应用准备到交接 **27.4 ms**，自动化观察到下载事件 **45.6 ms**，测试端保存完成约 **52.5 ms**。状态为 `current-state-unbound`、`frameAssociation:null`；应用回执仍是 `browserCompletion:"unobservable"`。应用只能确认交给浏览器，测试的下载事件与磁盘保存是另外两层观察。[实际状态 JSON](../qa/research-native-3.18/native-1/inspection-current-state.json) · [原生分阶段回执](../qa/research-native-3.18/native-1/report.json)

另一次 10,421,325 字节任务整库，通过真实 Worker、浏览器下载事件及有界保存完成：应用准备 **1346.2 ms**，本次下载/保存合计约 **1753.5 ms**，原始任务与矩阵逐值匹配。这是**毫秒**，与历史 **1758/2561 秒**挂起不是同一事件。[任务库独立下载记录](../qa/landing-archive-3.18/native-2/report.json)

最终检查还分开暴露了两个问题：旧 DOM 夹具在点击后立即读下载数组，先因真实异步准备而失败；改为最多 5 s 等待应用实际调用下载 anchor 后，原有整页 CJK 断言发现已完成的导出卡切至英文仍保留中文。4a9c 仅增加 `onLanguageChange(paint)`，没有重跑导出或再次交接。实际 JSDOM 单项保留全部元数据、物理和相机断言，并核对中英切换不新增 handoff、不改已导出 Blob 字节、不改回执状态。原 2aab 源码、两次失败及修复后新身份通过日志全部保留；这是接口回归，不是新增原生下载或 GPU 结论。[原始产品与失败身份](../qa/full-regression-3.18/pre-export-language-2aab/manifest.json) · [真实语言失败](../qa/full-regression-3.18/inspection-export-focused-after-attempt-1.log) · [4a9c 实际通过日志](../qa/full-regression-3.18/inspection-export-focused-after.log)

以上只说明这两次本地调用完成。用户原先 1758/2561 s 的工具挂起**没有在本机复现，不能宣布根因已解决**。当前加上的阶段回执有助于以后区分：应用快照、Worker、Blob、浏览器交接、外部工具文件传输。JavaScript 计时器不能抢占同步 GPU/浏览器主线程卡死，应用也不能观测操作系统下载完成。实际主应用采图时本地 `deployment.json` 不存在并报 404，报告保留这些错误，没有写成 console 空；原生隔离 Worker 验证则无 pageerror。

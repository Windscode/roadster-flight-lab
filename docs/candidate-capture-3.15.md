# 3.15 候选启动与待完成原生采集

本页是**可执行的复测入口**，不是已经完成的原生验收。当前公开网站仍是 3.13；3.15 候选以交付包内的 `deployment.json`、提交/源码树和 modelBuildId 为准。所有原生结果应绑定该身份，不能用旧图或数值夹具补位。

## 启动同一候选

已有候选仓库可直接执行 `npm start`。独立候选 ZIP 解压后，在包含 `site` 目录的位置执行：

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory site
```

Windows 使用已安装的 Python 时可将 `python3` 换成 `py`。随后打开 `http://127.0.0.1:8080/`；检视入口为 `/vehicle-inspection.html`，身份文件为 `/deployment.json`。请通过 HTTP 启动，浏览器直接打开文件路径不能可靠加载模块和 Worker。三维需要 WebGL 2；没有图形环境时，数值研究与历史导出仍有独立入口。

## 操控与任务

1. 城市中打开“记录这次驾驶 / 飞行”，分别执行 W 保持下 E→1、1→E、同时按下与短间隔；分别在地面/空中、G 开/关、0/20/50 km/h 测试，交替释放 E/1/W。随后在常驻状态区导出“最近输入时序”，并导出完整现场记录。输入时序为最近 20 秒的物理步窗口；超出滚动容量会明示丢弃数量。收到事件、控制层接收、实际参考/力矩和最终运动分别判读。
2. 按住驾驶/喷气/姿态键时切出窗口、打开面板或输入框，再返回。观察输入已释放、R 后暂停/P 继续、没有补跑异常步长。任务中途取消/接管、结束后返回城市；核对风、故障、气源与控制权。保留失败记录，不清空真实历史。
3. 按 M 选择车行入口导航，实际驾驶至上城驾飞挑战起点后开始。起点、18 m 地面段、起飞带、正向空中门及平台落稳条件以挑战运行前冻结规则为准。bench 与有限气源分别记录；传送、补气、复位或改物理参数不能算有效完成。
4. 实验室“控制律/着陆”中复制基线、修改 AST、运行对照/三组扫描、保存刷新，再选择候选进行同任务三维重执行。明确区分输入重放与新控制器重新决策。容量/拒写分支只在隔离 fixture 中测试。

## 图形入口与同条件要求

工程面板→渲染→“渲染完整性诊断”中已有：

- **高 / 极高切换检查 + 原始帧 ZIP**：14 帧、同帧具名诊断与总 manifest。先取消一次保留前缀，再重试完成；完整收集与实际 draw 通过是不同状态。
- **采集暂停帧与材质诊断**、**继续运行并采集实际驾驶帧**：用于核对暂停导出与普通可玩画面，不以 link/validate 成功替代颜色 draw。
- **重新下载最近采集包**：下载失败后保留本会话结果；真实下载与可解压性另行确认。

先锁定 1280×720、DPR 1、湿夜、曝光 1.02，对照高→流畅→高与极高；记录 GPU/驱动、画布实际像素、pass、FBO 尺寸和附件、每次 draw 错误。GL1286、主体缺绘、失败或取消必须原样保留。

车辆工坊保留原有 24 帧同条件采集及慢转入口。当前/基线固定同机位、姿态、曝光、分辨率和灯态；studio、自然光、城市湿夜分别看原车展示/实验版的正面、侧面、前后 3/4、轮毂和座舱。驾驶中另看反射、灯池与 LOD；Three 对象数检查不能代替像素或显存采样。

城市原生覆盖仍需完整织桥→横街→机造服务桥→连接坡道→上城议庭→原坡道返程→旧 canal→新水庭入口，再补低空及 120 m 四向。菜单到达不计驾驶覆盖。性能使用已有“预热 5 秒 + 采集 30 秒”，多段持续驾驶记录 CPU/GPU p50/p95/p99 与长帧，诊断帧剔除；暂停 FPS 和单点截图不计性能通过。

这些结果应汇入 [3.15 验收矩阵](acceptance-3.15.md)，不会因为候选代码完成或离线检查通过而自动关闭。

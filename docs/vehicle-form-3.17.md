# 3.17 车模主形体与实验室车身阴影

本轮在交付 3.16 的 `a0fce89e55efe6eaa54210987ef07cf9dfd7171e` 上修改现有参数车模。完成了前鼻的曲面和开口比例、顶面到侧面的真实肩部回边、连续门面，以及实验室漏接阴影修正的缺陷修复。材料颜色、粗糙度、玻璃处理和轮毂设计沿用 3.16。本说明的原图是实际 WebGL 输出，不含生成图或重绘图。

## 参考先于建模

实际打开并查看了用户提供的前侧 3.15/3.16 对照、座舱对照和研究观察图，也查看了 [Tesla 当前 Roadster 页面](https://www.tesla.com/roadster) 所链接的四张白色车官方原图：`Roadster-08-End-Desktop.jpg`、`Roadster-02-Pilot-Desktop.jpg`、`Roadster-03-Carousel-Slide-1-Desktop.jpg`、`Roadster-07-Augments-Desktop.jpg`。URL、下载字节数、SHA256 和逐项可见事实保存在 [参考复核索引](../qa/vehicle-form-3.17/official-reference-review.json)。官方图片没有作为游戏素材或本包附件复制。

照片能支持的判断是：上段黑色封闭鼻面与下段开口确实存在；白色鼻角有包裹转折，翼子板到侧面有曲率；尾部有可见金属喷口、风道和安装结构。照片不能提供原厂 CAD、校准镜头、隐藏机构尺寸或真实气路。此次具体宽度、圆角与深度是独立重建估计。

## 改了哪些真实几何

### 鼻部

旧黑色上鼻面约 1.350 m 宽、0.170 m 高，侧面近似竖直的矩形封盖。新的封闭上面约 1.258 m 宽、0.150 m 高，沿横向和前后方向形成弧面，下段仍是独立凹入开口。白色鼻角、开口回边、上下唇一起按这一曲面重建，避免通过更黑的材质制造一个假洞。前唇中央的视觉边缘向前移动约 9 mm，并抬高约 23 mm；物理碰撞、质量、惯量及喷口参数不由这份视觉文件修改。

保留了照片实际存在的宽黑色鼻面，不能把删掉这一特征当作还原。对比图显示其比例更收敛、白色鼻角有曲面，但整体仍是独立参数重建，不能声称已达到原厂造型或全量 3A 品质。

### 肩部、门面与轮拱连接

3.16 的顶面与侧面虽然位置相接，但在实际共享边界上，法线近乎垂直，产生“顶板接门板”的硬折。3.17 将顶面边缘向内收约 44 mm，直接把椭圆回边纳入侧面网格。回边深度由局部顶面斜率确定，使两边具有一致切线；没有在方盒上覆盖一条装饰圆管。门面使用端点斜率为零的连续压形，轮拱的原有真实开口和回边跟随同一侧面函数。

24 个跨三个 LOD 的真实射线交点对比显示，顶/侧法线夹角由 **76.70–83.47°** 降为 **0.33–0.81°**。这是几何连续性的证据，不是自动外观分数。轮拱与轮胎运动包络继续通过原有完整扫描。

| 车模档位 | 3.16 三角数 | 3.17 三角数 | drawable 数 |
| --- | ---: | ---: | ---: |
| 流畅 | 63,155 | 63,175 | 97 → 97 |
| 高 | 238,578 | 238,598 | 157 → 157 |
| 极高 | 394,374 | 394,512 | 157 → 157 |

以上为工坊车模成本，不是整个城市帧的 draw 数；新增面数来自鼻部回边，未新增车模 drawable。重用原有侧面网格，并将已有采样行集中到肩部转弯处。

### 座舱和尾部

左侧驾驶员眼点、车轮位置、悬挂行程、转向范围、轮胎/轮拱尺寸保持原值。车内、玻璃与尾部金属喷口、风扇盒及安装肋的既有几何保留；本轮没有把旧改进再计为新成果。匹配的座舱和尾后原图用于检查这项保持情况。尾部仍有简化和较暗的内腔，不能以“有结构”声称已达到照片级细节。

## 研究观察图斜条纹的原因

这轮分开检查了网格法线、纹理和阴影路径。

- 肩部硬折是几何/法线连续性问题，上述真实回边解决它。
- 机盖中央 12 个真实射线交点的位置和法线在前后车模中完全一致，法线差为 0；车漆的颜色、金属度、粗糙度、清漆保持原值，颜色/法线/凹凸/粗糙度/金属度贴图均为空。因此中央机盖的周期性斜带没有被“换纹理”掩盖。
- 城市与工坊会给车辆材料接入已有的逐采样点阴影接收面深度修正；实验室直接创建车模，漏掉了该接线。现在在 `createRoadster` 公共材料工厂幂等安装同一修正，城市和工坊原有调用继续兼容。

实际实验室候选图中，3.16 机盖/门板的密集斜条带已消失。车辆仍投射阴影、接收阴影，场景光源、阴影图尺寸和曝光没有因这项修复改变。工坊 shader 审计与各材料编译注入合同均通过。实验室地面和远处设施仍有原有简化及阴影边缘问题，本轮结论只覆盖车辆。

## 验证、失败和未测

**实际通过：** 新增 `tests/vehicle-form-3.17.test.mjs` 从完整 Git 历史加载冻结 3.16 及相关依赖，比较主形体/肩缝/阴影/成本；原有 `vehicle-geometry.test.mjs`、`vehicle-surface-3.10.test.mjs`、`vehicle-finish-3.16.test.mjs` 通过。后两者沿项目既有报告命名辅助函数写入 3.17 报告，未覆盖历史。几何扫描覆盖 1,774,080 个轮胎/轮拱扫描采样，以及座舱、灯腔、LOD、剖切等原有合同。实际像素人工复核已看完上述 12 张有效前后原图，没有发现此次改动造成的新大片穿插。

**迭代中失败并保留：** 初次侧面边界法线不连续；鼻部折返的退化边出现零法线；侧面采样重新分布一度不满足已有内部样点合同。这些都修改后通过。日志保存在 [iterations](../qa/vehicle-form-3.17/iterations)。第一版工坊采图脚本因座舱相机重组约 1e-15 的舍入差误判失败，原报告和 PNG 保留；后验检查用明确的 1e-12 浮点公差验证该组参数，不修改原失败记录。两张菜单遮挡的实验室截图也保留并标记为无效证据，最终单独使用正确暂停按钮补了无遮挡图。

**浏览器限制：** 工坊记录了两条 HTTP 404；实验室记录了一条 404 和当前软件渲染器不支持 `KHR_parallel_shader_compile` 的警告。旧采图记录未带 404 URL，不能擅自认定其全部来自 favicon，也不能说控制台零错误。开发时 `deployment.json` 和 `favicon.ico` 不在 dist 中，HDR 环境纹理存在且已加载；最终交付身份由整轮构建流程另核验。无 WebGL shader 编译/链接失败在本轮有效图的审计中出现。

**未测：** 用户显卡的持续帧时、所有天气/相机的视觉覆盖、原厂尺寸公差和真实光学材质校准。未进行重复慢转视频或大量重复采图。

## 独立 JSON 下载现象

本轮工坊采图实际触发了 10 次已有的“当前状态 JSON”按钮，均落盘。Playwright 从分发点击到浏览器下载事件的墙钟时间为 **1.720–3.169 s**，从下载事件到保存完成约 **1–5 ms**。这是软件 GPU 负载下、包含浏览器调度和渲染的外部工具测量，不是 JSON 编码时间，也不是与 3.15/3.16 不同导出路径的速度对决。

本轮没有复现 1758 s 的工具挂起，也没有据此宣称用户问题已修。QA 脚本为下载事件设 30 s、落盘设 20 s 上限；它没有更改产品导出逻辑。全部下载记录与原始 JSON 见 [candidate/capture.json](../qa/vehicle-form-3.17/candidate/capture.json)。

## 文件范围

产品变化仅涉及 `dist/vehicle.js` 和工坊当前版本静态标签 `dist/vehicle-inspection.html`；公共阴影算法沿用既有 `receiver-plane-shadows.js`。工坊内置原样冻结的最新比较模型仍为 **3.15**，按钮保持真实的“3.15 / 3.17”身份。此次严格 3.16 对照来自独立冻结工作树，并没有给内置 3.15 换名。

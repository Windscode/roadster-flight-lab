## 打开候选

独立候选 ZIP 解压后，在包含 `site` 目录的位置运行：

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory site
```

Windows 已安装 Python 时可使用：

```powershell
py -m http.server 8080 --bind 127.0.0.1 --directory site
```

打开 `http://127.0.0.1:8080/`。车辆工坊在 `/vehicle-inspection.html`，部署身份在 `/deployment.json`。通过 HTTP 打开才能可靠载入 ES 模块、Worker 和纹理；直接双击 HTML 不等于同一运行条件。

完整源码历史包包含本轮原分支提交和原 3.15 历史。新目录可以从完整 bundle 克隆；已有 3.15 checkout 可先核验增量 bundle 的前置提交，再作为普通 Git 源取回到独立候选分支。无需强推、删除历史或重建原项目。恢复大文件使用项目既有机制：

```sh
git clone --branch improve/roadster-3.14 roadster-flight-lab-3.16-full-history.bundle roadster-flight-lab-3.16
cd roadster-flight-lab-3.16
node scripts/repository-payloads.mjs restore
npm start
```

分块恢复校验原长度、SHA-256 与 Git blob SHA，并保留已有本地编辑。候选发布准备使用严格校验；本地文件与所审查归档不符时停止，不静默覆盖。

已有 3.15 源仓库时，可在该仓库核验增量的前置提交，再取回到新的普通分支；把下面 bundle 路径替换为实际下载位置：

```sh
git bundle verify /path/to/roadster-flight-lab-3.16-from-3.15.bundle
git fetch /path/to/roadster-flight-lab-3.16-from-3.15.bundle refs/heads/improve/roadster-3.14:refs/heads/review/roadster-3.16
git switch review/roadster-3.16
node scripts/repository-payloads.mjs restore
```

增量以前置提交 `9f6c8f47a2678beee3915a0320ac2bf93312e96b` 为界。最终交付另有完整历史恢复、增量前置／恢复、候选每文件长度和 SHA-256 的实测回执。候选界面原“源码下载”链接仍指向 GitHub main；在本轮发布获准完成之前，需要本轮源码请使用随交付提供的完整历史或增量 bundle。

## 这次可直接看的改动

城市驾驶状态区显示供气、控制权、风／故障、姿态 P/R、累计俯仰／滚转与 G 回平状态。X 接收、拒绝、当前阶段与结束回执持续保留；详情中可看能力限制并导出最近输入时序。直接使用状态区的暂停／继续，可停住现场观察，不需要复位车辆。

W 持续保持时可以追加 E、1，G 开启时显式让出驾驶者俯仰请求；松键后的回平和推力／力矩不足要合看实际姿态、控制权与气源。R 复位会释放输入并暂停，P 恢复。X 仍为原快速低高度动作，不能仅用单次截图间隔判断它是否发生。

按 M 选择既有车行入口导航，沿细街、Crosstown 和东侧连接去机造。新增铺面没有替代原道路；本轮额外发现的 z=−100 横街路沿遮挡已经修正。固定相机采集和菜单选择入口不计入连续驾驶覆盖。

本轮已经在冻结 `28e9bc41…` 上另行执行一次原生连续驾驶：从原城市出生点沿 Weave → Crosstown → Foundry **下层车行入口**，现有导航实际报告抵达并刹停，随后完成原研究记录保存和 JSON 下载。190.4 s／22,848 步的原生记录及起终点完整 PNG 分别保存；到达使用原有 8 m 半径，记录终点距目标水平约 5.906 m。上层连接、维护庭和 `z=−100` 横街的横向穿越不由本次路线覆盖。[实际路线、接触与日志边界](native-city-drive-3.16.md) · [完整原件和图片](../qa/city-drive-native-3.16/index.html)

研究台提供“操作／观测”“结果分析”和“收起观察”三个工作区。专业参数、控制图、曲线和完整结果仍在原库中；新任务使用同一生产求解器。完成、失败、取消和保存状态分开显示。结果首屏解释落稳、平台稳定／超调与气量，同条件才给差值，固定时窗与全任务气量分列。

## 原生采集约束

最后 3.16 原生运行在开始／结束分别读取服务器实际源码和三套光场。`model-build.js` 里显示正确标签还不够；每个声明的源码文件、光场 manifest、实际体积文件长度和 SHA 都要与实际提供内容一致。如果过程中有源码或烘焙变化，该次采集保留为中间证据，不重新贴最终标签。旧 3.15 十张城市对照在采集前核对完整候选文件、每帧保存原构建／光场身份，之后补做完整 HTTP 源码与光场读取；没有把后来添加的前后审计字段伪装成当时已经存在。

固定城市前后图使用 1280×720、DPR 1、high、相同技术相机与同天气；白天曝光 0.87，湿夜 1.02。PNG 从应用 ZIP 原样提取，检查 ZIP CRC、图像可解码性与同帧条件绑定，不调亮、修图、裁掉问题或用概念图补位。主页面驾驶座舱另采，和车辆工坊的棚内照明分开解释。

原生操控脚本只通过普通按键及可见产品控件操作，不写车辆位置、四元数、输入值、控制器状态或时钟。达到高空试验条件时实际按 E 爬升，记录越过 120 m 时状态、制动后的真正起始高度，再持续 W 后追加 E/1。这个高空试验不能覆盖地面起始条件。

实际输入 journal 采用现有有界窗口和 2400 项容量，说明已丢弃数、首末物理样本与未覆盖时段。长时间 E 爬升另保留约 2 s 仿真间隔的公开 telemetry 稀疏读数；它不能证明采样间完全无碰撞。截图前后 telemetry 只构成时间括号，除应用同帧导出外不称为精确同帧姿态。

软件 GPU 渲染会使墙钟与仿真时间不同步。操控时间按真实 `simTime` 等待，原始 key 事件墙钟也保留；没有修改 `performance.now()` 或补跑时钟。正常渲染、诊断帧、应用导出和外部自动化等待各自记时，不用暂停 FPS 或烘焙耗时作性能结论。

## 保留的反例与未验证边界

- 原 3.15 湿路反射在实际 draw 出现 GL1282，并有 Chrome feedback-loop 报错。本轮冻结该旧逻辑后修复活动 sampler 与写目标同纹理问题；最后 14 帧的 28 次实际 draw 检查通过，原始旧错误及中途两次超时不覆盖。开发服务器 deployment.json 404 仍留在新报告。
- 本轮早期三站轮胎支撑产生制动微偏航，门灯在建筑包络内，Foundry 新路沿横挡旧横街，城市部分视点超预算，主线程分片导出在实际渲染下变慢。修前记录均保留，修后对原门槛回归。
- 本次连续原生驾驶已抵达 Foundry 下层入口并刹停、保存导出，但不称全程零 compound 接触。独立只读几何更支持车轮硬限位触地，实际接触 pair、形体 ID、力和冲量未采；外部日志缺 8 条 `returned`、原报告与遥测实存行数相差 1，均不回填。上层连接、`z=−100` 横向穿越和维护庭仍未由本次路线验收。[原始证据与明确边界](native-city-drive-3.16.md)
- 90 km/h、10 cm 台阶的完整轨迹在更高步频仍未收敛，峰值大冲量和失稳不删；独立几何重叠与接触方程深度分开报告。
- 有限气源提前回收保留“原任务取消、回收落地”，不改成原任务完成。原有限气源失败继续保留。
- 目标用户显卡的帧率、输入手感、硬件滚键、全城所有入口／上下层／返程及完整玩法组合，需要相应实机证据；当前局部证据不扩大范围。

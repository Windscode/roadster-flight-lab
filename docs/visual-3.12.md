# 3.12 图形进度与同条件验收

## 本轮真实看到了什么

本轮从两个原始 ZIP 读取了 3.9 城市、检视与官方参考图的像素，也再次读取了用户上传的 1205×667 车身横纹 PNG。织桥湿夜中首层、路缘和建筑暗部缺少结构；南岸日景的连续窗带、街道尽端和远景仍显单薄；前机盖、翼子板的规则密集条带与玻璃分层仍是需要隔离的真实缺陷。当前官方参考的楔形与硬折线继续保留，不把它改成圆润旧概念车。

这些是历史输入证据，不是本轮完成画面。原始来源、哈希与分辨率见 [3.10 证据记录](visual-evidence-3.10.md)和 [3.11 条纹来源](../qa/body-stripe-source-3.11.json)。两批图分辨率、车辆位置和状态不同；暂停约 27 FPS、瞬时 HUD 数字与未核实的 GPU 均不能用来作行驶性能结论。转向截图的实际速度为 26→22 km/h，不是 68 km/h 验收。

3.11 已发布至提交 `ab9372b56a01c2a47b18d32baf48162f3cd8f86c`。2026-10-20 04:23 UTC 刷新实际线上页面后，浏览器显示 `CITY + WIND LAB / 03.11`，但图形上下文创建失败：`GL_VENDOR = Disabled, GL_RENDERER = Disabled`，并显示“当前图形环境不可用，研究仍可继续”。这是本轮使用的云浏览器后端限制，不能据此判断用户设备或网站本身不能渲染。

**本轮没有可用的当前版本三维后图，没有目标 GPU 帧时，也没有宣称车身条纹、夜色或材质观感通过验收。** 数值界面的真实浏览器截图另行标记，不能代替三维画面。

## 仍需完成的真实三维对照

### 车辆：同机位隔离条纹

进入 [车辆检视](https://windscode.github.io/roadster-flight-lab/vehicle-inspection.html?view=front-lamp)，选择当前模型。在“条纹与曲面隔离”中导出“同机位七项隔离 ZIP”。前灯、前四分之三和正侧各成一组，条灯与自然光分别成组。

每组依次包含完整材质、关闭接收平面校正、关闭车体接收阴影、关闭环境贡献、漫反射灰模、视空间法线和网格。应用会冻结相机、模型、LOD、悬架、转向和尾翼，并把每张真实 PNG 与同帧条件绑定。只有后图中相应条纹确实消失，且接触阴影、曲面轮廓与高光没有出现新的问题，才可以作视觉结论。

3.9/当前模型切换使用当前渲染器，适合几何对比，不能当作两套历史渲染流水线的完整对比。隔离模式改变了照明或材质分量，也不能当作默认成品截图。

### 城市：暗部、局部光与反射运动

保持同一设备、浏览器、DPR、实际 drawing buffer、画质、相机、车辆状态和曝光。1280×720 高画质为一组，2031×1244 另成组；晴天和湿夜分别比较。

1. 织桥、交换厅、桥下、横街、南岸各固定机位预热后使用“保存真实画面 + 同帧条件 ZIP”。检查未被近处动态灯照到的路缘、首层、门廊、混凝土和桥底是否仍有层次。
2. 固定相机与车辆分离：车从视野近处驶过，改变刹车灯、转向与尾翼状态。检查捕获区域内道路积水中的车辆与灯具倒影是否跟随实际变化，确认没有沿用原 0.35 s 静止复用路径造成的冻结后跳变。
3. 移动相机穿过静态/动态漫射过渡带，并穿过湿路反射原区域边界。升高到 14–18 m 应逐步退出该平面反射；不应在 18 m 附近整块闪断。
4. 保持其他条件不变比较干燥沥青、湿膜与局部积水；检查车漆、玻璃、混凝土和金属的相对反光、阴影接触与抗锯齿。不要用整体曝光或换有利灯光代替机制验证。
5. 行驶完整环线，包含机造大道、横街和南岸尽端。检查近、中、远景连续性以及既有不同街区的实际区别，不能只采一个好看的入口。

### 性能与日志

将加载、5 s 预热、暂停和连续驾驶分段；随后采集 30 s 或完整 150 s 路线。保留 rAF 帧时 p50/p95/p99、长帧、实际分辨率变化、CPU 分段及可取得的 GPU query。GPU 身份不可取得时记为未知。固定相机暂停刷新不作为行驶 FPS。

目标浏览器的 X3595 / X4000 日志仍需采集并关联实际输出。离线 GLSL 检查能发现语法和接口问题，不能证明目标 ANGLE/驱动警告已经消失，也不能把一条警告直接认定为可见缺陷。

## 未关闭的图形验收项

当前版本车身横纹根因的最终像素隔离、默认夜景暗部与材质观感、移动灯池与反射稳定性、全路线真实帧时、远景及城市边界重设计均继续保留在[原开发计划](../AUDIT-AND-CHANGES.md)。已有曲面、照明和预算修复不因本轮浏览器限制而回退，验收也不因数值测试通过而删除。

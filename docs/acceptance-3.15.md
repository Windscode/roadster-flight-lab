## 身份与阅读规则

**当前为本地 3.15 开发/测试候选，尚无 3.15 远端提交或部署。** 原 3.14 一段合成数值压缩载荷的公开上传，经逐项来源核查仍被 automatic approval review 拒绝；具体公开记录见[发布阻塞](../qa/publication-blocker-3.15.json)。线上 [deployment.json](https://windscode.github.io/roadster-flight-lab/deployment.json) 仍是旧基线，不能用于绑定本候选。最终本地验证与候选身份以 [qa/validation-final-run-3.15.json](../qa/validation-final-run-3.15.json) 及随后准备的 `.pages-site/deployment.json` 为准；后者是不纳入仓库的生成文件，准备完成不等于网站部署完成。

本轮基于已恢复的 3.14 提交 `f4b96c5caa9652d812e0f2df1e3e3dfe1074abb3`，保留其完整提交、源码、报告和载荷。恢复、打包与同树发布不是本轮功能增量。不在本表填入未知提交、旧构建 ID 或未经最终执行确认的聚合数量。

本表的“已测试”必须连同证据层级阅读。开发期专项与最终聚合是两次执行；最终聚合负责确认相同构建的复跑结果。修前夹具、历史归档和原失败继续保留各自身份，不能统一改标成当前构建。 大体量数值 JSON/逐步轨迹可由[无损载荷清单](../repository-payloads/manifest.json)存储；在仓库运行 `node scripts/repository-payloads.mjs restore` 后，以原文件名与哈希读取。压缩/分块只改变传输形式，不抽稀数据或转换成新的验收证据。

# Roadster Flight Lab 1.1

本轮基于已发布的 1.0 `88ddb11` 重新审查四条主线，并核查实际页面与既有原始记录。实现集中在可复现的物理边界、车体几何缺陷、渲染准备和实验结果可靠性；没有改写历史验收，也没有以增加推力或抓地力代替修复。

## 审查与修复

| 方向 | 实际发现 | 1.1 行为 |
| --- | --- | --- |
| 喷气与气源 | 控制预算使用环境压力，实际执行器仍按固定 1 bar 降额。罐压与环境同为 2 bar 时仍有推力，并可能一步耗尽气体 | 喷口、能力预算、悬停与着陆预测共用压差系数；零压差不产生推力、不耗气 |
| 电力与机构 | 空电池仍可主动转动尾翼；只剩 1 J 时控制执行器仍能获得完整一步能力 | 按同一步电机功、回充与辅助用电判定供电；失电翼面保持实际位置，气动力继续按实际部署计算 |
| 着陆判断 | 旧预报只看初始电量是否大于零，在未来几十秒预测中不扣电 | 扣除辅助用电，活动或仍旋转的风扇按额定功率保守预留；显示预计耗电/余电。存在驱动油门或电机负荷时明确不提供该垂直预测 |
| 车体外形 | 前折边与包角约 15.90 mm 错台、前开口两侧漏面、侧面切线断接 | 共用边界和相切回卷，补齐真实漏面；三档三角形和绘制批次不增加，机械硬点与材质不变 |
| 城市渲染 | 同一材质的多个程序变体没有全部等待完成；迟到资源可能改绑编译中的材质；无界等待可能使界面卡住 | 先等待资源稳定，再用有期限的非阻塞检查等待已提交程序；失败退出准备并恢复记录/数值研究入口。准备状态显示当前阶段 |
| 夜间反射 | 反射已消费的全局阴影请求在恢复状态时又被置回 | 主视图复用已消费的请求，失败仍保留待更新请求；这是减少重复准备/遍历，不宣称所有阴影贴图绘制减半 |
| 实验档案 | 多页面保存可能覆盖另一页面新增分析，或复活已删除记录；执行中导入可能使结果脱离当前档案 | 核对原始内容与共同采样，合并独立追加分析；执行中阻止替换源记录。删除/内容冲突保护旧档案，完整会话结果可导出、明确重试；畸形分析在导入阶段拒绝 |
| 复盘与改键 | 以前的 A/B 和复算虽保存在记录里，却只能显示最后一项；部分动作提示仍写死 X/U/G | 可选择原记录及每次分析，并单独导出；控制归属、动作回执和回平提示随实际按键绑定与语言更新 |

3.24 和 1.0 的完整兼容记录可显式按 1.1 重算。只迁移声明的版本字段，不补造缺失状态，不执行旧求解器；来源身份保留，重算结论明确不要求与旧模型轨迹完全相同。

GitHub 中英文首页重写为面向使用者的项目介绍：实际画面、可用能力、第一次驾驶、研究流程、模型限制和可运行的本地启动步骤。历史开发说明保留链接，不再将旧候选说明混作当前功能介绍。仓库简介、网站入口与主题标签一并整理。

## 保留的能力与工程边界

- **物理与操控**：地面轮胎/悬架/接触、ABS/TCS、飞行控制、组合输入、翻转与落地已有实际实现，本轮保留其有效成果。默认条件以真实 1.0 内核和资源层作逐步对照。辅助供电不足时，执行器截止最多提前一个积分片；轮胎、机构和辅助功耗仍属明确工程近似。
- **模型**：保留座舱、底部、喷口、活动部件和不同材质。[车体审查](vehicle-review-1.1.md)说明公开图片依据与独立造型假设。车壳碰撞体有简化，轮胎不是弹性有限元模型，不能称为原厂工程 CAD。
- **城市**：保留完整连续城市、不同区域、路口/坡道/高架、首层陈列、光照与现有性能预算。本轮优化渲染生命周期，没有宣称新增城区、建筑室内或商业 3A 体量。
- **研究和玩法**：风场、控制律、资源路线、着陆挑战、完整快照及有效输入共用现有求解器。加强了档案和多次分析的闭环，没有新增只有入口的研究模块。localStorage 并非跨进程事务数据库；检测到并发冲突时保护数据并提示，不能承诺任意时序下的分布式原子性。
- **易用性**：核查首页到路线/研究的入口、模式交接、暂停/重试、相机与声音的状态映射。头部惯性仅影响显示，音效仍由实际状态合成且可关闭；没有把数值检查当作主观音频听感或实体手柄认证。

## 验证入口

[当前发布门禁](../qa/release-1.1/validation.json)包含数值、资源、几何、DOM、发布与本地启动检查；[真实浏览器验收](../qa/browser-1.1/observations.json)单独记录实际界面、车模、重放与性能。新证据仅写入 1.1 路径，旧报告和失败反例保留原身份。

本次 65 项当前发布检查全部通过。真实浏览器完成白天与湿夜各 21,600 步原条件重放，终态和已存曲线通过一致性检查；实际 1.0 记录也完成 21,600 步显式重算，并保留“不要求旧模型复现一致”的结论。大结果触发 4 MiB 上限时，实际界面保留旧档案、标注会话未保存，并成功导出完整所选分析。

另外完成高 / 极高 / 流畅与昼夜组合的 14 帧真实绘制矩阵，材质链接与绘制检查通过，物理状态不变，原始 PNG 和同帧条件保存在浏览器证据目录。此检查独立于驾驶性能采样；首次生成部分极高画质材质有明显等待，不能把诊断完成解释为瞬时切换保证。

RTX 4080 SUPER、1280×720 高画质的两段 150 秒活动采样：白天帧耗时中位数 / P95 / P99 为 6.1 / 12.1 / 12.3 ms，2 个超过 50 ms 的长帧，最大 60.6 ms；湿夜为 6.1 / 12.2 / 18.2 ms，没有超过 50 ms 的长帧，最大 36.5 ms。两段均另保留 5 秒预热，分辨率不变。驱动缓存可能已热，本次不是冷启动或受控版本提速对照，不能据此宣称全部设备或全城每个位置无卡顿。

shader 准备完成只表示已提交程序满足当前驱动就绪检查，不保证所有未来绘制都没有长帧。实际设备、画质、采样条件和未消除的长帧以浏览器报告为准。着陆余量是一维、近水平、低横速的仿真建议，不预测横向障碍、未来指令或故障，也不代表实车安全保证。

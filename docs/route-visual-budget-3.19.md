# 3.19 连续路线：视觉成本与身份约束

此约束在新的视觉专项验收前登记。它保留原有城市和预算，不用三角形数量证明画质，也不把 Three 几何统计称为 GPU 性能。

## 固定范围

沿现有织桥街从 `(-200,-380)` 行驶到 `(-200,-132.5)`，再左转（A）进入横街至 `(-145,-132.5)`，中心线长 **302.5 m**。路面区域从 `route-surface.js` 的同一描述读取，不复制另一份湿区地图。原 114 栋建筑、12 条道路、物理壳体及 3.18 橱窗、光源、烘焙场保留。

光学字段 `opticalWetness`、粗糙度与接触附着字段 `gripScale` 分开。普通天气依然只是观赏条件；显式准备这条路线后，其区域内光学状态与接触条件都由准备时的描述确定。运行时改昼夜不改变描述。平齐钢板和补面只改表面响应，没有视觉假凸起，也不增加碰撞台阶。

## 预登记成本上限

- 使用现有道路着色器：最多 12 个矩形区域，新增 0 个纹理、0 次纹理读取、0 个道路 draw call、0 个屏幕 pass。区域 uniform 原始载荷不超过 416 字节。
- 新维修口与桥接构件共用现有实例材质与图集。新增几何上限 12,000 三角形，新增纹理字节为 0；不引入新光源，不更改阴影尺寸、级联数和 probe 预算。
- 原 `qa/exterior-materials-check.mjs` 的 15 视点约束保持：每档 draw calls 不超过 `qa/exterior-baseline-3.5.json` 的原上限，每视点三角形不超过同基线 110%；balanced 另须小于 300 draws / 650,000 triangles。
- 原完整环境 `qa/render-budget-check.mjs` 的 balanced 小于 400 draws，以及相对原 3.4 几何提交减半的条件保持。
- 真实 GPU 帧时与显存验收按本轮整体验收计划的固定设备、分辨率、画质与路线执行。云端软件光栅、离线 shader 链接、Three 估算与 HUD FPS 均不能填写为这个硬件结果。

## 美术差异与观察点

两个明确的维修入口替换原首层的两个开间，其他 3.18 展示橱窗保留。双门、折边框、阈石、独立观察窗和带厚度的通风片形成一套复用模块；回边、后板和顶底封口在斜视时真实存在。门把手中心仍为 1.06 m。它们位于原封闭碰撞壳体，不能进入室内。

`z=-320/-172` 两座既有人行桥增加沿原桥板高度的折边、拼接板、壁面承托饰面与步廊接合盖板。构件附着于原板和墙，不降低净空、扩大路面或添加车道内支撑。它们是原体量的连接与收口表现，不宣称重新计算桥梁结构。

固定复查机位可采用：桥前 `[-200,2,-332] → [-200,5,-318]`；横街入口 `[-167,1.8,-139.5] → [-166.4,1.7,-149.3]`。必须同时保留路线驾驶图和普通白天/转角观察，夜间单幅摄影不代替体验通过。

## 可核接口

环境 `setRouteSurfaceDescription(descriptor|null)` 只接收已验证的描述；`getRouteSurfaceDescription()` 返回独立副本；`stats.preparedRoute` 暴露活动状态、哈希和区域数。失效或退出路线时可明确传 `null`，恢复现场时重新绑定保存的描述。天气和质量 setter 不修改这份状态。

物理表面版本、原记录与研究条件由对应记录链保存。维修口和道路光学改动不会使旧物理记录偷偷绑定新表面。

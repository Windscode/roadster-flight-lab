# 3.18 车模：后升腰线、长尾座舱与白颊体量

本轮从完整 3.17 历史的 `d9a4fbfd434fe49cdbeae18c32f624360e9dc4e9` 接续，修改现有参数车模的主形体关系。侧面腰线、座舱后段、前白颊和深色侧裙有真实几何变化；车漆、玻璃颜色与粗糙度沿用前版。这里的对照图来自实际 WebGL 帧，不是生成图、重绘图或为了展示而替换的车身模型。

## 主形体变化

### 侧影与座舱后段

3.17 侧影的后车肩接近水平，后窗提前落下，后甲板因此显得平而长。新模型将门后及后翼子板肩线抬起，肩线在模型 `z=.73` 至 `z=-.76` 间向后的高度增量由 **0.044 m 变为 0.098 m**。门缝、把手和侧面压形跟随同一个真实表面，不靠增画一条线表现腰线。

后风挡末端从 `z=-1.57` 延伸到 `z=-1.78`，重新分配后段 canopy 高度站点，使顶冠后方不再过早跌落。玻璃、窄密封、车顶侧边、C 柱面和后甲板开口一起跟随，后窗落脚处连接更高的后车肩。尾翼保持原有固定位置与状态，后甲板尾段保留安装间隙。顶冠的最高位置和宽度未整体放大。

深色侧裙改为上沿向后抬高的封闭体积，实际替换下部门面，而不是在原白色车门外叠一条细轨。左右两侧同一射线位置在 3.17 命中白色车漆，在 3.18 命中碳色侧裙；此项只证明模型存在真实的材质分区和体积变化，外观判断仍看完整侧面原图。

### 前白颊、翼子板与风挡落脚

鼻端半宽由模型的 `.855 m` 调整为 `.910 m`，接近鼻端的翼子板站点也相应加宽；hood 前端半宽从 `.647 m` 调整为 `.620 m`。这增加了角面 hood 两侧的白色包裹体量，并保留中间的宽黑色上鼻面、独立下开口和原有灯腔。白颊的横向分布从集中到窄圆端盖的曲率改为更宽的角面，边缘继续有真实回边。

先使用 3.17 已有的正前照片拟合机位检查，再修改风挡。该机位下，前版风挡下沿偏窄，而顶冠没有同等程度的偏窄证据。因此只将风挡落脚半宽从 `.775 m` 调整到 `.885 m`，通过中间站点连接原顶冠。**这 0.110 m 是独立重建参数的改变量，不是从照片量出的原车差值。** 没有为让照片投影误差变小而重设相机、灯光或轮心。

当前白颊仍比官方图更直立、偏方，灯腔和侧面细部也有简化。本轮让主轮廓关系更接近参考，不能宣称已经完成原厂级还原。进一步修型应继续看同机位整车轮廓和跨视角关系，不应以更多倒角或更低法线夹角代替。

### 尾腔与既有机构

新增连续的折入式尾部腔口周边，形成外框、向内回折和原尾面之间的深度。后灯槽和周边白色回边随抬高的尾肩衔接。四个冷气喷口、四个下部抽吸风道和安装肋仍然裸露；没有通过封盖隐藏机构。喷口中心和朝向保持原值，尾翼物理位置与入射角保持原值。

尾腔近图可以看到新的周边层次，但较大的平面、风扇和支承仍是工程化简化结构，不能当作官方内部机构的复刻。

## 保留的硬点与物理边界

本轮车模工作没有修改物理质量、惯量、碰撞求解器或执行器力参数。轮心、轴距、轮距、轮胎半径与宽度、悬架行程、轮拱内包络、最大转角、左侧驾驶员眼点、喷口中心和固定尾翼位置逐项保持。视觉外壳不自动生成物理碰撞壳；车辆落地、台阶、控制权和喷气问题由本轮独立的连续状态验证负责。

原有轮胎/轮拱运动扫描、座舱和真实开口检查继续通过。没有因修型而扩大轮包络容限，也没有放宽碰撞或动力学限制。材质采样器与表面阴影接线保持，不以关闭自阴影获得更干净的静态图。

### 身份与画面限制

基线实际报告 `3.17.0 / 26692f4324d2392ae7ac5981709299e2f6da29929259221445a7ba49591781d4`；本组候选实际报告阶段值 `3.18.0 / 5b9ff8f6a852198bd6e6dfcdbc9779c9dd8e65877b598a26e6fa6bdc08d95faa`。候选当次加载的 `vehicle.js` SHA256 为 `9b197c22e595f559dd8769dc167a1646a6ac686f3b30ceb1435725ccd1507bc9`。每组浏览器日志记录真实收到的 JS/CSS 源文件 SHA，未用后续统一构建身份回填旧截图。完整渲染/导出代码在版本间不完全相同，固定光学条件相同不等于整个渲染器字节相同。

Chrome 156 使用 ANGLE SwiftShader。此组图不能代表用户 GPU 的持续帧时。两个端口均出现开发环境 `deployment.json` 404，并有未附 URL 的资源 404。照片拟合视图的远程参考缩略图请求出现 `ERR_CERT_AUTHORITY_INVALID`；四张官方原图已独立下载并实际查看，形体对照不依赖失败的网页缩略图。不能把控制台描述为零错误。

## 检视参考点同步

`vehicle-display-study.js` 原有照片镜头、焦距、相机位置、目标、图像偏移和人工照片 UV 全部保留。模型侧的鼻端、肩点、风挡落脚、顶冠和窗尾点改为读取实际当前表面；新导出的 canopy 采样函数与建模共用同一组站点，避免检视表继续引用旧高度。前后点位记录在 [reference-landmarks.json](../qa/vehicle-form-3.18/reference-landmarks.json)。

这同时改正了参考点定义和实际几何，新的二维残差不能与旧数字直接比较并称作“还原提升百分比”。残差仍混合镜头假设、人工标注与模型误差。工坊说明已经明确这一限制。

## 验证、失败与未测

实际通过 `vehicle-form-3.18.test.mjs`、更新后的历史 `vehicle-form-3.17.test.mjs`、`vehicle-finish-3.16.test.mjs`、`vehicle-display-3.14.test.mjs`、`visual-quality-3.13.test.mjs`，以及原 `vehicle-surface-3.10.test.mjs` 和 `vehicle-geometry.test.mjs`。新增验证只围绕本轮真实形体改变及其不应影响的硬点；视觉改善由上面完整图判断，不以断言数或零件数证明。

原历史测试中“hood 与 3.16 完全不变”“所有显示站点冻结”“总法线转角与旧型相差不足三度”是当时分析条纹来源或细部抛光范围的条件，不能当作未来主形体永远不变的要求。本轮明确移除这些旧外观等式并记录差值，继续保留硬点、轮拱、真实开口、有限法线、真实接缝小于八度、物理包络与原渲染预算约束。没有为了通过而放宽物理容差。

整轮 `attempt-5` 又发现 3.13 光学历史合同仍要求 hood 宽度、所有表面站点和玻璃 footprint 与旧型完全相同。该 [失败日志](../qa/full-regression-3.18/attempt-5.log) 保留。测试现在仍要求冻结 3.12 参考表面与玻璃边界精确不变，当前轮拱、内衬、漆面和采样器也保持；当前视觉站点变化明确列入报告。纵向 hood 接缝射线跟随真实新宽度，旧射线 X 坐标保留，原 0.5 mm 深度容差、邻接漆面、玻璃排序、LOD/剖切后精确还原与 `+1 drawable / <4%` 资源约束均未放宽。该最终测试与原 3.10 表面、3.18 硬点短检查再次通过，产品字节没有为旧测试改回旧形体。

初次前翼子板站点产生约一度的纵向局部反坡，原表面测试失败；随后修正站点，原反坡约束原样通过。尾腔框最初过密采样使历史渲染预算失败，减少薄框纵横细分后通过，预算没有放宽。历史外观冻结检查和受限沙箱 Git 子进程失败也分别留在 [iterations](../qa/vehicle-form-3.18/iterations)，未删除或覆盖失败记录。最初一组采图保存在 `candidate-r1`，继续保留当次旧版本标识及源 SHA，不冒充最终候选。

通过的资源边界只是维护可玩性的检查：工坊三档 drawable 数没有增长，三角数相对 3.17 增幅不足 1%。它们不作为形体完成标准。未测原厂尺寸公差、真实材料光学参数、用户 GPU 的持续性能；运行阴影稳定性另有 [连续驾驶、转向、相机及昼夜原生记录](shadow-native-3.18.md)，其中失败、阶段身份和软件帧时限制独立保留。

## X 的实际短沿与动作

每次先设独立 Node 50 ms 定时器，再发送 keydown；keyup 不等待 keydown 的协议回复。预先声明的短沿条件是有序、可信、非重复的 down/up，且 API、DOM 时间戳和页面观察回调间隔分别大于 0、至多 100 ms。各实测值如下，不称精确 50 ms 或硬件键盘认证。

| 场景 | API 间隔 ms | DOM 时间戳 ms | QA 观察回调 ms | InputSession 接收 ms | 实际回执 |
| --- | ---: | ---: | ---: | ---: | --- |
| 正常城市静止承载 X | 50.077618 | 48.400000 | 1.700000 | 1.500000 | 路由接收，物理动作接受 |
| R 复位暂停后 X | 50.203813 | 50.400000 | 1.400000 | 1.200000 | 原启动路径恢复并接受动作 |
| 菜单占用时 X | 50.767301 | 51.000000 | 2.700000 | 2.500000 | 路由与动作均拒绝，保留具体原因 |

第一组 keydown 协议回复约 1018.830 ms 后才返回，但 keyup 已在 50.078 ms 发出。浏览器队列使两个事件最终紧邻处理：事件到观察回调的绝对延迟分别约 1013.6／966.9 ms。因此 API、DOM、QA observer 和生产 InputSession 是四个不同口径；不能说应用一直按住了 48.4 或 50 ms。它实际接受了 1.5 ms 接收间隔的一对输入沿，松键没有取消已接受的快翻。

## 地面 W → E → 1 与 G：两组均未完成后翻／回平

高空组标记起态到首个生产样本有 **0.491667 s 的 W-only 准备头缺口**。随后 **30.566667–44.158333 s 共 1632 个控制样本没有内部 step 跳号**。俯仰启动前一帧 30.633333 s 到回平后的 44.158333 s 连续，故俯仰一圈与 G 回平的整段有完整接触与姿态记录；不能把这称为从整个标记起点毫无缺口的视频。

摘要另直接用实际四元数旋转车体上向量，再展开其世界 YZ 平面投影角：约 0° → −412.302096° → −360.000000°。相邻采样变化最大 0.596°，投影长度始终至少 0.999999411、面外 X 分量最大 0.001085，因此这里的展开没有退化或跨越大角跳变。它独立支持这次近似平面俯仰确实转过一圈，并与连续零接触和末态回平一起判断；不是从欧拉 pitch 或单个累计数字推断成功。

窗口仍是 20 s 墙钟／20 s 仿真和 2400 个事件上限。`droppedEvents` 是全局滚动丢弃数，可能只是更早的组被挤出，不能直接当作当前组缺失的物理帧数。采集结束状态与时序下载是两次读回，部分时序比标记末态多约 0.075／0.083 s；全部真实时间保存。HUD 暂停试验与菜单拒绝组没有启用物理时序，不用零条样本推出零接触。

可见“暂停／继续”按钮通过真实点击触发既有路径。同一个点击的 capture/bubble 观察夹证显示物理状态不跳变；W 仍保持按下时点击暂停，应用释放它，约 **2138.031 ms** 的实际暂停观测期间物理状态不前进；继续后没有复活旧油门。整个采集共有 10 次该按钮的真实点击，夹证状态均一致。

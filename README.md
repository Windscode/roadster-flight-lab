# Roadster Flight Lab

**把一辆车，从街道开到空中；把一次驾驶，变成可以解释和重放的实验。**

简体中文 · [English](README.en.md)

[**进入城市 ↗**](https://windscode.github.io/roadster-flight-lab/) · [风场实验室](https://windscode.github.io/roadster-flight-lab/?view=lab) · [车辆工坊](https://windscode.github.io/roadster-flight-lab/vehicle-inspection.html)

Roadster Flight Lab 是一个独立、可玩的车辆与飞行仿真研究项目。依据 [Tesla 当前公开的 Roadster 图像](https://www.tesla.com/roadster)重建外形，在原创 Vesper 城市中探索驾驶、冷气推进、姿态控制与近表面吸附。轮胎、悬架、气体、喷口、尾翼和控制器共同作用于同一个六自由度刚体。

沿连续街道驾驶，离开路面完成姿态机动，再把输入和响应变成可导出的实验。风、观测延迟、喷口降额和有限气源会实际改变结果；成功、失败与取消分别保留身份。

## 第一次怎么玩

1. **开一段街道。** W / S 加速与制动，A / D 转向，Space 车轮制动。沿织桥、横街、机造服务桥与连接坡道去上城，再从原坡道返回南岸。地图可帮助辨认路线；相机避障不改变行车路径。
2. **离开路面。** H 开启辅助飞行，E / Q 上升与下降。滑条直接设置升降目标，范围 0.5–14 m/s、默认 5 m/s，另有四个响应预设。实际响应受推力、供压、气量和姿态约束。仪表中的世界高度与附近表面距离含义不同，包络距离标为估计。
3. **练习姿态。** G 开启时恢复水平滚转与俯仰，保留切换时的航向；此时 Z / B 为横移。关闭 G 后，Z / B 滚转、1 / 2 俯仰。松键制动仍需要实际力矩与时间。
4. **记录，再回来。** 选择“记录这次驾驶 / 飞行”，停止后在研究控制台查看轨迹、曲线和输入事件。导出完整 JSON；保存状态确认成功后，刷新仍可打开记录。R 会复位并暂停，按 P 继续。

默认恒压外部供气方便练习；有限车载气源会耗尽并降温。两种模式均保留阀门响应与喷口上限。界面支持 **中文 / English**，编辑表单时驾驶与流程快捷键暂停接收。

### 快翻，也保留真实惯性

X 保留独立的 `quick-roll-1`：短起跳、快速滚转，再通过实际喷力制动与返回。气源、初始姿态 / 角速度或上方净空不合适时，显示具体拒绝原因。3.13 真人恒压记录已完成滚转并最终返回 DRIVE，也记录了超调；这不保证精确 360°、原地落点或所有初态成功。

手动练习可选 **快翻练习**，H 开启辅助飞行、关闭 G，先 E 起升再 Z / B 滚转；约四分之三圈时松键并开 G 尝试制动回正。G 使用当前高度参考，不自动回到起跳高度。时序、失败工况与气源差异见[快翻对照](docs/x-flip-3.13.md)和[当前物理说明](docs/physics-controls-3.14.md)。

## 从一个着陆任务开始改控制律

进入[风场实验室](https://windscode.github.io/roadster-flight-lab/?view=lab)，打开 **研究控制台 → 控制律 / 着陆**。

1. **先跑默认任务。** 检查任务预览中的高度、风时序、供气与落稳条件，点击 **三维挑战 / 重试**。默认从静止地面起飞到 2.5 m 世界重心高度，经历两段侧风后下降到半径 1.5 m 的目标区。第一次触地不等于成功，必须继续落稳。驾驶输入可接管，也可“取消 / 交还控制”。
2. **真正改一次控制组合。** 从 PD 或“积分 + 滤波”模板开始，编辑 JSON 控制图中的误差、比例、积分、滤波与限幅组合。此入口只控制高度外环；输出进入现有受限控制、喷口分配、阀门和气源。它不执行任意 JavaScript，也不能直接改刚体位置、速度或姿态。
3. **让新算法重新决策。** 保存控制图，用 **原算法与编辑算法对照** 对同初态、同任务运行两种算法。先核对初态、模型、风、供气与任务差异，再读曲线。条件不一致的结果标为描述性比较，原有“固定输入 A/B”也继续保留。
4. **看清成功与失败。** 检查落点、接地垂速 / 姿态、饱和、气耗与关键事件。个人最好只比较同条件下成功落稳的记录，不用总分掩盖撞地。有限气源与恒压外供气单列；外供气吞吐量不是车载储罐消耗。

“后台同任务研究”可在不移动现场车辆的情况下计算同一任务。任务主统计使用全部 120 Hz 物理数据；展示曲线为 20 Hz，历史抽稀另行标明。算法、任务、输入输出、版本和失败事件随完整 JSON 保存。当前默认风扰较温和，V1 使用确定性风时序，不代表任意扰动下的安全保证。[接口范围与实验结果](docs/research-platform-3.14.md)。

已有研究也继续保留：**G 恢复高度网格、五种子控制器对照、干湿 / 分离附着制动、有限气源边界、现场记录与复现判定**。城市和实验室分别保留车辆状态，自动流程可绑定到 3–9。

## 在工坊里看清两种身份

[车辆工坊](https://windscode.github.io/roadster-flight-lab/vehicle-inspection.html)提供 **原车外观 · 双座展示** 与 **实验改装 · 单座**。前者依据公开图像重建可见座椅、中央区、门板和顶棚；后者保留气瓶、管路、四点带与实验硬件。

**两者仅为检视展示配置。切换不会重建质量、惯量或碰撞，不会改变驾驶车辆或历史记录。** 未公开的内部结构和喷口安装关系仍是工程推测，摄影内参未知，地标误差只用于设计对比，不是 CAD 精度声明。

固定技术机位和估计摄影匹配机位分开。可以切灯态、扫查转向与悬架、观察尾翼，或在同光棚对照冻结的 3.13 / 3.9 / 3.8。导出的六机位棚光 / 自然光对照含真实帧与同次条件；城市湿夜须在主城单独采集。新增双座身份没有被伪装成旧版本已有的对照配置。

## 保存你的研究

结果页将 **执行状态、物理结果、持久化状态** 分开。出现 **“仅本会话 / 未保存”** 时，计算可能已经完成，但刷新前应先导出当前完整结果或整库 JSON；稍后的完成提示不会清除这条警告。

浏览器容量仍有限。追加失败保留旧磁盘记录，新成果留在本会话可导出；删除、清空和保存控制参数先验证写入，成功后才更新已保存状态。损坏、未知版本或含非法条目的旧库保留原文并只读隔离，可以导出备份，不自动清空历史腾空间。语言切换不改用户名称、算法内容与实验值。

旧记录仍可阅读、导出。精确重执行要求兼容的模型、协议和碰撞身份；不支持的跨版本完整快照会明确拒绝，可在当前模型新建任务生成新记录。[保存行为与兼容边界](docs/research-platform-3.14.md)。

## 模型与画面边界

这是依据公开图像和工程假设制作的非官方仿真，没有 Tesla 原厂 CAD、轮胎数据库或实车标定。额定机械功率 **700 kW**、干地摩擦系数 **μ = 1.25**、单主喷口 **20 kN** 均为当前模型假设。物理包含轮速、联合附着、悬架接触、有限响应阀门、气源和受限分配，不含工业 CFD、柔性车身或完整多体悬架；松油电机制动按机械耗散建模，未计电池回充。

3.13 指定高档湿夜视点的楼面与道路恢复已有真实 GPU 绘制和像素证据，旧密集阴影条纹也已有隔离验证。3.14 继续修复极高离屏目标和采集流程，但不能用链接成功或数值测试代替实际绘制。最终构建的极高矩阵、全路线画面、运动稳定、驾驶手感及 CPU / GPU 帧时仍需目标设备补验；这不是已经完成的全城 3A 成品。具体条件和未覆盖项见[渲染说明](docs/rendering-3.14.md)。

Tesla 官方 [The Kickflip | Roadster](https://www.youtube.com/watch?v=r5vsHHPVhJg) 可作为动作观感参考；官方来源不等于提供了可标定的质量、供压、精确高度或工程遥测。

## 本地运行

需要 Node.js 22+；运行依赖已包含在仓库。

```sh
git clone https://github.com/Windscode/roadster-flight-lab.git
cd roadster-flight-lab
npm start
```

打开 `http://127.0.0.1:8080/`。Windows 也可双击 `启动试验场.cmd`。三维需要 WebGL 2 和图形加速；数值研究无需 GPU。
